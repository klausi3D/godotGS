# Release Acceptance Bar

What GodotGS must satisfy before it is released, and how that is verified.
Resolves the question posed in issue #360.

Two stages. **Public Alpha** ships earlier on a reduced bar and says "alpha" on
the tin. **v1.0 Production** is the full bar below. Every claim in either stage
must be backed by a lane, an evidence bundle, or a named human signer — a claim
with none of those is not a claim, it is a hope.

Recorded against base `de2cb8007ba` (2026-09-03). Code citations below were read
at that commit; re-verify before relying on them.

## 1. Release intent

**v1.0 is production-ready**: someone can ship a commercial game with it.

This sets the height of everything else. Where a decision below looks expensive,
that is the intent being honoured, not scope creep.

## 2. Supported platforms

| Platform | v1.0 rung | Notes |
| --- | --- | --- |
| Windows | `production-tested` | Primary target; self-hosted GPU runner exists. |
| Linux | `editor-tested` | Requires a real-GPU lane (see work items). |
| macOS | `build-supported` | Explicitly disclosed as unvalidated. |

Rungs are the ladder in
[`docs/reference/compatibility-matrix.md`](../reference/compatibility-matrix.md).

Linux at `editor-tested` is **not** satisfied by the current CI: the Linux lane
today runs neither the `qa` nor the `sorting` categories (#596). Both must be
wired into a GPU-backed Linux lane.

## 3. Performance bar

**Peer-relative, measured out-of-band.** GodotGS must be at least as fast as
comparable published Gaussian-splatting renderers on the *same splat files*,
compared against those renderers' *published* numbers. This is a release-time
exercise; it is deliberately **not** wired into CI.

In-CI benchmark baselines (#523) therefore serve **regression detection only**.
They answer "did we get slower than ourselves"; they never answer "are we fast
enough". Do not let a green benchmark lane stand in for the peer comparison.

### 3.1 Two published figures

GodotGS carries real-time lighting, shadows and effectors that peer renderers do
not. A raw comparison conflates "slower renderer" with "doing more work", so the
release publishes two numbers:

- **Parity** — extras inactive, like-for-like against peer published numbers.
- **Feature cost** — the marginal ms of each extra, measured on the same scene
  and camera path.

### 3.2 How the extras are made inactive — and the trap

Cost is driven by **scene composition**, not by a feature switch. Verified at the
base commit:

- **Lights** — `gs_accumulate_directional_lights` bounds its loop by
  `scene_data_block.data.directional_light_count`
  (`shaders/includes/gs_lighting_common.glsl:60`). A scene with no light nodes
  runs zero iterations.
- **Shadows** — `shadow_strength = 0.0` makes `shadow_sampling_enabled` false
  (`shaders/tile_binning.glsl:1298-1299`), skipping `gs_directional_shadow()`.
  The QA project already pins this, so the configuration is known to render.
- **Effectors** — `effector_count == 0` early-returns
  (`shaders/includes/gs_deformation.glsl:29-30`).

**Trap — do not use these as an "off" switch.** `direct_light_scale` and
`indirect_sh_scale` are applied as post-multiplies *after* the accumulation work
(`shaders/tile_binning.glsl:1367`, `shaders/tile_resolve.glsl:383`). Setting them
to zero blanks the image while paying the full cost. A parity number produced
that way is false.

**Residual, disclosed not hidden:** even at zero lights the shader still carries
the lighting path — the `params.lighting_config.z > 0.5` branch
(`shaders/tile_binning.glsl:1306`), normal computation, SceneData binding and its
register pressure. Parity is therefore *close to* a peer renderer, not identical
to one compiled without lighting. State this alongside the number.

## 4. What blocks a release

The bar states a **rule**. The blocker list is regenerated by query at release
time, so it cannot go stale.

**Blocking:**

1. Any defect a user can hit in a supported configuration, inside the supported
   envelope (§5).
2. Any gap that makes the readiness claim itself uncheckable — a metric collected
   but never compared, a lane that passes without executing, a benchmark that
   measures less than it names.
3. Any documentation claim the code contradicts (§8).

**Not blocking:** internal refactors with no user-visible and no evidence effect.

Rationale for keeping refactors out: a rule that blocks the release on
"decompose `publish()`" predictably ends with P1s being relabelled P2 to unblock,
which is the same shape as weakening a gate to make a check pass.

## 5. Supported envelope

v1.0 claims **full scope**: single-scene resident rendering, multi-node scenes,
and streaming open worlds. Anything outside the envelope is not a promise.

Because streaming and multi-node are *inside* the envelope, their defects are
user-visible-correctness blockers under §4.1 by definition. This is the most
demanding of the envelope options and is a deliberate choice.

## 6. Visual proof

**Human eyes on real-scan content.** Synthetic CI fixtures (2k–30k splats) keep
their regression role, but they do not carry the "looks right" claim — GPU-001
was absent under production defaults while every counter reported success, and a
QA pin masked it (#903, #921).

Required at release, across the supported envelope, plus the exhibition recipe
and an FSR2 motion-ghosting check. This generalises the condition already bound
to the #921 fix.

**Binding:** a dated evidence bundle committed in-repo carrying screenshots,
metrics, the asset's content hash, and a named human signer. The asset itself is
referenced by hash and never committed.

## 7. API and settings stability

**A bounded public surface.** All 193 project settings are classified as
`public` / `internal` / `debug_only` / `deprecated_alias`. Public settings carry
a stability promise and real behavioural coverage. Everything else is documented
as subject to change.

At the base commit the manifest
(`modules/gaussian_splatting/config/project_settings_manifest.json`) records 193
settings of which **3** are marked `public`, **150** carry no `publicness` at
all, and **139** are `inventory_only` — present in the inventory with nothing
verifying they do anything.

A promise over a surface that large is unkeepable; a small kept promise is worth
more than a large broken one.

## 8. Disclosure

**Known issues are generated, not hand-written.** Release notes list every known
issue reachable inside the supported envelope, derived by query, each with an
observable symptom and a workaround where one exists. Hand-maintained lists in
this repository have drifted from source every time they were audited.

**A wrong doc is a user-facing defect** and blocks under §4.3. A doc that asserts
behaviour the code no longer has sends a user to debug their own project for our
bug — strictly worse than no doc. Known instances of this shape are listed in the
work items.

## 9. How the bar is verified

**Fail-closed machine gate, plus a named human signer.**

Machine-checked, failing closed on anything missing or absent:

- the §4 blocker query returns empty;
- every required lane **ran** and passed;
- the §6 evidence bundle exists, is fresh, and its hashes resolve;
- `publicness` is set on every setting in the manifest.

Human-signed, because these are product judgements:

- the real-scan visual pass;
- the peer-comparison numbers;
- the accuracy of the known-issue disclosure.

**"Ran" is load-bearing.** A job-level `if:` yields `conclusion: skipped`, which
counts as SUCCESS against a required check — a silent total bypass. The gate must
assert execution, not merely the absence of failure. See
[evidence integrity](evidence-integrity.md).

## 10. Public Alpha — the reduced bar

The alpha exists so that design errors are found early by users rather than late
by us, while the v1.0 program is still being built.

| | Public Alpha | v1.0 Production |
| --- | --- | --- |
| Envelope | Single scene, resident, ~2M splats | + multi-node + streaming |
| Blocks | User-visible correctness only | + evidence integrity (§4.2) |
| Visual proof | Real-scan human pass **required** | Same, across full envelope |
| API stability | **No promise**, stated plainly | Bounded public surface (§7) |
| Peer comparison | Not required | Required (§3) |
| Gate | Human sign-off | Fail-closed gate + sign-off (§9) |
| Labelling | "Alpha" stated prominently | — |

The real-scan visual pass is required at **both** stages. An alpha may ship with
gaps; it may not ship with splats missing under its own default settings.

## 11. Work items this bar creates

Derived from the decisions above; each needs its own issue and none is closed by
this document.

**Blocking v1.0, from the full-scope envelope (§5):**

- #842 — no benchmark lane varies node count; the hundreds-of-nodes target is
  unproven, and GrandmasHouse was CPU-bound at 113 nodes.
- #318, #320 — streaming performance.
- #786 — `qa_stream_visual_smoke` never reaches visual readiness on a real GPU.
- #883 — GPU streaming stress `frame_p95_to_avg_ratio` 3.69 on an idle runner.
- The 50M chunked open-world asset must become a passing lane, not a contract.

**Blocking v1.0, from the bar itself:**

- Linux GPU lane, with the `qa` and `sorting` categories wired in (#596).
- Classify all 193 settings; guard that `publicness` is always set.
- Behavioural coverage for every setting classified `public`.
- Build the §9 fail-closed release gate; register it in the policy machinery
  list in the same change.
- Generated known-issue disclosure (§8).
- Peer-comparison harness and writeup (§3), out-of-band.
- Evidence-bundle format and location (§6).

**Blocking the Public Alpha:**

- #921 / GPU-001 — splats absent at viewport scale 0.75 and under FSR2 with
  `composite/depth_test = true`, the shipped default.
- Real-scan visual pass on the alpha envelope.

**Newly identified, not previously tracked:**

- `enable_direct_lighting` is the true master gate for the lighting path
  (`shaders/tile_binning.glsl:1306`), but it is hardcoded `true` at
  `renderer/render_pipeline_stages.cpp:2253` and
  `renderer/tile_renderer.cpp:1376` and is exposed by no project setting; only a
  unit test sets it false (`tests/tile_renderer_regression_test.cpp:927`). A game
  shipping plain splat rendering with no lights cannot skip that path. Needs an
  issue.
- Docs asserting behaviour the code contradicts (§8). Two confirmed at the base
  commit: `docs/performance/gs_quantization_tradeoff.md:63` still calls quantized
  assets "effectively unlit", a symptom fixed in #510; and
  `renderer/sh_config.h:33` documents SH band 3 as "16 coefficients = 48 values"
  while `PackedSphericalHarmonics::MAX_ENCODED_COEFFICIENTS` is 12
  (`renderer/gaussian_gpu_layout.h:239`), so three band-3 coefficients are
  silently dropped even at full quality. A sweep for further instances is itself
  a work item.
