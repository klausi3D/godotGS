54// Lock ordering (acquire in this order to prevent deadlocks):
55//
56// Level 1. submission_mutex (outermost — serializes GPU submission)
57// Level 2. resource_maps_mutex (protects gaussian_buffers / buffer_lookup / dynamic_asset_cache)
58// Level 3. active_nodes_mutex (protects the active_nodes set)
59// Level 4. local_device_destroy_request_mutex / local_device_destroy_pending_mutex
60// (innermost — local-device teardown dispatch and pending-device handoff)
61//
62// Rules:
63// - Never acquire a lower-numbered (outer) lock while holding a higher-numbered (inner) one.
64// - In practice no method currently nests two of these locks in the same scope;
65// the ordering is documented here so that future changes preserve this invariant.
66// - The destructor acquires them sequentially (not nested):
67// active_nodes_mutex -> release -> resource_maps_mutex -> release ->
68// local_device_destroy_request_mutex/local_device_destroy_pending_mutex -> release.
69//
70// Validated at runtime in DEV_ENABLED builds via thread_local lock-level tracking
71// (see _gs_lock_level_guard in the .cpp file).
