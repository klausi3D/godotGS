21 // Overlap record budget for global composite sort pipeline.
22 // Each Gaussian that overlaps a tile generates one record. A scene with N splats
23 // where each covers ~M tiles on average produces N*M records. Close camera views
24 // or large splats can push this multiplier to 50-100+.
25 // Default: 100 million records (~1.2 GB VRAM for key+value buffers).
26 // Minimum: 100,000 (for small test scenes).
27 // Maximum: ~200 million (practical VRAM limit; 2.4 GB for buffers alone).
28 uint32_t max_overlap_records = 100000000;
29 // Optional lower bound used by adaptive overlap budgeting.
30 // Kept <= max_overlap_records via accessor clamp.
31 uint32_t max_overlap_records_adaptive_min = 100000;
32 // Enables the adaptive overlap-budget feedback loop in TileRenderer: the global
33 // composite-sort capacity is sized from MEASURED overlap demand (peak + 20% headroom)
34 // instead of the loose visible*50 pre-count estimate (~2.5-4x over-reservation).
35 // Default ON (GS-PERF-S2). REQUIRES bounded_buffer_shrink_enabled to actually reclaim:
36 // adaptive lowers the estimate, but the only-grow capacity stays pinned at its
37 // high-water until the shrink path frees it; conversely the shrink is floored by the
38 // visible*50 estimate unless adaptive lowers it. Both flags are on together by default.
39 // Sizing never drops tiles: a same-frame post-count auto-grow covers any spike, and
40 // max_overlap_records_adaptive_min bounds the floor. See the overlap-estimate /
41 // adaptive-floor logic in TileRenderer::RenderFrameExecutor::_execute_global_sort_pipeline.
42 // Project-setting overridable to false in both directions.
43 bool adaptive_overlap_budget_enabled = true;
44 // Enables bounded shrink of only-grow GPU scratch buffers so a single zoom-in
45 // spike no longer pins peak VRAM for the rest of the session. Gates the global
46 // projection buffer AND the global composite-sort key/value buffers; the separate
47 // instance/depth sort buffers are a future extension behind this same flag.
48 // Default ON (GS-PERF-S2): trades an occasional buffer realloc for much lower
49 // steady-state VRAM. Measured on dense-2M: sort buffer 572 MB -> 34 MB (-538 MB) with
50 // no dropped records (overflow_splats_clamped stays 0 across grow-after-shrink) and no
51 // frame-time regression (the shrink-recreate is not a measurable hitch). Pairs with
52 // adaptive_overlap_budget_enabled — alone this reclaims only when the visible count
53 // drops; together they reclaim the ~2.5-4x over-reservation at steady visible.
54 bool bounded_buffer_shrink_enabled = true;
55
56 // Soft cap for per-tile raster iterations in fragment/compute rasterizers.

108 // GPU Performance Tier Presets
109 // These presets configure sorting parameters optimized for different GPU capabilities.
110 //
111 // LOW TIER: Integrated GPUs (Intel UHD, AMD Vega), older discrete GPUs
112 // - Minimizes memory usage and compute load
113 // - Smaller workgroups for better occupancy on limited hardware
114 // - 64-bit keys (the only shippable layout): 32-bit depth keys band and
115 // flicker on real-scan content, so no preset selects them. 32-bit keys are
116 // an explicit gpu_preset="custom" + key_bits=32 opt-in only.
117 //
118 // MEDIUM TIER: Mid-range discrete GPUs (GTX 1060, RTX 3050, RX 5600)
119 // - Balanced settings for good performance and quality
120 // - Standard workgroup sizes
121 // - 64-bit keys for better precision
122 //
123 // HIGH TIER: High-end GPUs (RTX 3070+, RX 6800+)
124 // - Maximum throughput settings
125 // - Larger element counts and workgroups
126 // - Full precision and monitoring enabled
127 //
128 // ULTRA TIER: Enthusiast GPUs (RTX 4090, RX 7900 XTX)
129 // - No compromises, maximum quality
