4// ADR docs/architecture/adr-hlod-streaming.md sections 6.2, 6.9 and 14.3 (package C, slice S2b).
5//
6// The precise CPU world frame: a flat Cartesian frame whose positions are an integer lattice
7// address plus a double offset inside the lattice cell. Nothing here is a bound API.
8//
9// - PreciseCoord: lattice address (int64 per axis, edge LATTICE_EDGE metres) plus a double
10// offset in [0, LATTICE_EDGE). Differences of two coordinates are formed on the integer
11// addresses first, so they are exact at any distance from the frame origin.
12// - PrecisePlacement: rotation*uniform scale (float basis) plus a PreciseCoord translation.
13// - WorldOriginContext: the origin of the GS render frame. Every origin change bumps a
14// revision; frame-dependent caches and snapshots key on it. It never touches scene nodes.
15//
16// Payloads stay node-local floats; a view-dependent offset is only ever computed per draw
17// (camera_relative_offset) and is never stored with shared payloads.

27// 2^10 m. A power of two, so cell*edge and all lattice arithmetic below are exact in double.
28constexpr int LATTICE_EXP = 10;
29constexpr double LATTICE_EDGE = 1024.0;
30// Largest accepted |cell| so differences of two coordinates cannot overflow int64.
31constexpr int64_t MAX_CELL = int64_t(1) << 60;

33struct PreciseCoord {
34 int64_t cell[3] = { 0, 0, 0 };
35 double local[3] = { 0.0, 0.0, 0.0 }; // In [0, LATTICE_EDGE).

54};
