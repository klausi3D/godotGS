8// Atomic file write for the persistence/import savers.
9//
10// The savers historically did `FileAccess::open(path, WRITE)`, which truncates
11// the destination immediately and then streams content. A crash or write error
12// mid-save leaves a truncated/empty file, destroying the previous good copy
13// (worst case: the baseline the incremental-delta system depends on).
14//
15// `gs_atomic_file_write` instead streams the content to a sibling temp file and
16// only moves it into place once the whole write has succeeded and the file has
17// been closed. The final move is a TRUE atomic replace-over-existing
18// (`MoveFileExW` on Windows, `rename()` on POSIX), so a concurrent reader always
19// sees either the old or the new file and never a missing target. On any
20// writer/rename failure the pre-existing destination is left byte-intact, and the
21// temp is cleaned up.
22//
23// Caveats (see docs/architecture/adr-import-input-hardening.md):
24// - The atomic OS replace is the primary path and needs no backup. If it is
25// unavailable or errors, the helper falls back to a backup-swap: it moves any
26// existing target aside first (so each `DirAccess::rename` targets a
27// non-existent path, avoiding Godot's remove-then-move Windows data-loss
28// window) and restores it if the final move fails. The fallback's only
29// residual window is a crash BETWEEN the two moves, and even then no data is
30// lost: both the backup (old contents) and the temp (new contents) remain on
31// disk for recovery.
32// - `FileAccess::flush()` is a CRT-level flush AND Godot ignores its return
33// value, so a flush-only failure is not surfaced here. Write-completion is
34// therefore validated by the caller's per-write `get_error()` checks (the
35// writer lambda must return non-OK on any failed store); this helper's
36// flush()+get_error() is a secondary check. A true fsync (power-loss
37// durability) would need an upstream engine primitive.

53// #714: default no-op pre-rename guard, so callers that need no exclusivity around
54// the rename pay nothing and keep the two-argument call shape. It establishes
55// nothing, so there is nothing that can fail to be established: always drained.
56struct _GSAtomicNoRenameGuard {
57 bool drained() const { return true; }
58};

60// Writes `p_final_path` atomically. `p_write` is invoked with the open temp file
61// and must return OK on success; it must NOT retain a persistent Ref to the file
62// beyond its own scope (transient Refs passed to helper functions are fine).
63//
64// `p_make_rename_guard` is invoked with no arguments immediately before the atomic
65// rename, and whatever it returns is kept alive until the rename has finished. It
66// exists for writers whose destination may be held open by other readers: on
67// Windows the rename needs delete access, which an open FileAccess denies (#714).
68// Scope it to the RENAME ONLY -- the copy above can take arbitrarily long, and any
69// exclusivity held across it would stall readers for the size of the file.
70//
71// The guard must expose `bool drained() const`, reporting whether it actually
72// established that exclusivity. When it returns false the rename is NOT attempted:
73// its precondition is known to be violated, so it would fail and report whatever
74// the filesystem says about a rename that never had a chance, burying the real
75// cause. The temp is removed and ERR_BUSY is returned instead. A guard that
76// establishes nothing returns true -- there is nothing for it to fail at.
77template <typename TWriter, typename TRenameGuard>
78Error gs_atomic_file_write(const String &p_final_path, TWriter &&p_write, TRenameGuard &&p_make_rename_guard) {
79 String temp_path;
80 Error open_err = OK;
81 Ref<FileAccess> file = _gs_atomic_open_temp(p_final_path, temp_path, &open_err);
82 if (file.is_null()) {
83 return open_err != OK ? open_err : ERR_FILE_CANT_WRITE;
84 }
85
86 const Error write_err = p_write(file);
87 if (write_err != OK) {
88 file.unref();
89 _gs_atomic_remove_temp(temp_path);
90 return write_err;
91 }
92
93 file->flush();
94 const Error io_err = file->get_error();
95 // Drop the sole reference so the OS handle is closed BEFORE the rename;
96 // Windows cannot rename over / move an open file.
97 file.unref();
98 if (io_err != OK) {
99 _gs_atomic_remove_temp(temp_path);
100 return io_err;
101 }
102
103 // Guaranteed copy elision (C++17) constructs the guard in place, so it needs no
104 // copy or move constructor. It lives until this scope ends, i.e. across the
105 // rename and nothing else.
106 auto rename_guard = p_make_rename_guard();
107 if (!rename_guard.drained()) {
108 _gs_atomic_remove_temp(temp_path);
109 return ERR_BUSY;
110 }
111 return _gs_atomic_rename_temp(temp_path, p_final_path);
112}
