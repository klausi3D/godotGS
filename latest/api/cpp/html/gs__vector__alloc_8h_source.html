3// #794: checked Vector::resize() for the "resize then write[]" pattern.
4//
5// Vector<T>::resize() reports allocation failure through its RETURN VALUE and leaves
6// the vector at its previous, smaller size: CowData::resize() -> _fork_allocate()
7// hits ERR_FAIL_NULL_V(mem_new, ERR_OUT_OF_MEMORY) and returns before size() is ever
8// touched (core/templates/cowdata.h). Code that ignores that return and then writes
9// vec.write[i] for i < requested_count walks off the end, and CRASH_BAD_INDEX in
10// core/templates/vector.h hard-traps the whole process via __fastfail(7).
11//
12// CRASH_BAD_INDEX is NOT gated on DEBUG_ENABLED, so this is a hard crash in EVERY
13// build configuration including release -- not a latent corruption. It is exactly how
14// the nightly GPU Streaming Stress lane died in #787 (0xC0000409, fast-fail subcode 7,
15// symbolized to VectorWriteProxy<PackedGaussian>::operator[]).
16//
17// The read path traps identically: Vector::operator[] const -> CowData::get() also
18// asserts CRASH_BAD_INDEX, so a site whose write loop is bounded by the vector's own
19// size() can still trap on a later indexed read.
20//
21// This generalises the file-local _reserve_pack_output() that #793 introduced for the
22// pack sites. It deliberately keeps that helper's two properties:
23//
24// 1. Report count, element size and total bytes. That is the diagnostic the crash
25// itself can never deliver, which is the whole reason #787 needed symbolization.
26// 2. Leave the output EMPTY, never partially sized, so no caller can consume a
27// truncated buffer. Trading a loud crash for silent data loss would be worse
28// than the bug.
29//
30// [[nodiscard]] is load-bearing, not decoration: #793 established that making a
31// function fail closed is not enough if a caller ignores the result -- three of its
32// four callers consumed the empty output, one handing buffer_update() a null pointer
33// with a nonzero byte count. Ignoring this result is a compile error.
34//
35// ---------------------------------------------------------------------------
36// SCOPE RULE: which resize() calls need this
37// ---------------------------------------------------------------------------
38// A call needs checking when the index written afterwards is bounded by the
39// REQUESTED count rather than by the vector's own size(). Two exclusions follow from
40// that, and they are rules, not a curated exception list -- which matters, because an
41// invariant guarded by a hand-maintained list is already broken:
42//
43// 1. The index is bounded by the vector's own size(). A failed resize shrinks the
44// bound along with the buffer, so the write stays in range. NOTE this covers the
45// write only: a *later* indexed read against a different bound can still trap
46// (see the pair in gaussian_streaming.cpp vs render_streaming_orchestrator.cpp,
47// where one traps and one does not, for exactly this reason).
48// 2. The count is a compile-time constant that does not scale with scene, asset or
49// file data (a literal, or a fixed ring-buffer capacity). The index then cannot
50// exceed what a successful resize produced, and a failure means the allocator
51// could not serve a handful of small structs -- the process is already gone.
52// Sites excluded this way carry a one-line comment naming this rule.
53//
54// Everything else -- any count derived from splat counts, chunk counts, file headers,
55// or collection sizes -- is in scope. Those are the allocations that can realistically
56// fail, and #787 is the proof that they do.

72// #798 review round 3: a test cannot reach the FAILURE branch below by choosing a large
73// count. Every caller in scope validates its count first, and any count big enough to
74// actually exhaust the allocator is rejected by that validation long before it gets here
75// -- proven on a sibling PR. Without a seam, a test that claims to cover a fail-closed
76// rollback path in fact runs the SUCCESS path and passes with the rollback deleted.
77//
78// So arm one specific call site by its `p_where` label and let the real
79// gs_resize_or_fail() take its real failure branch. The test drives the code under test,
80// not a test-only shortcut around it.
81//
82// Properties that make this safe to have in the tree:
83// * Compiled out entirely unless TESTS_ENABLED. Nothing ships (#725 shipped test hooks
84// in a release build once; this must not repeat).
85// * Matched by label, not "next call". A one-shot "fail the next resize" latch would be
86// consumed by whatever unrelated allocation happens to run between arming and the
87// target -- non-deterministic, and silently mis-aimed.
88// * One-shot: the arm is cleared by the firing, so a single armed site cannot leak into
89// later cases in the same process.
90// * Atomic pointer, no allocation and no String work on the disarmed path, so an armed
91// test cannot race a worker thread that also allocates.
92// The armed pointer must have static storage duration (pass a string literal).
93inline std::atomic<const char *> &gs_vector_alloc_forced_failure_site() {
94 static std::atomic<const char *> site{ nullptr };
95 return site;
96}

114inline bool gs_vector_alloc_consume_forced_failure(const char *p_where) {
115 const char *armed = gs_vector_alloc_forced_failure_site().load(std::memory_order_relaxed);
116 if (armed == nullptr || p_where == nullptr || strcmp(armed, p_where) != 0) {
117 return false;
118 }
119 return gs_vector_alloc_forced_failure_site().compare_exchange_strong(
120 armed, nullptr, std::memory_order_relaxed);
121}

124// Resizes p_vec to p_count. On success returns true. On allocation failure clears
125// p_vec, emits an error naming the sizes, and returns false; the caller must then
126// apply its OWN failure contract (return false / return an Error / skip the entry).
127// It deliberately does not choose one.
128template <typename T>
129[[nodiscard]] bool gs_resize_or_fail(Vector<T> &p_vec, int64_t p_count, const char *p_where) {
130 if (p_count < 0) {
131 p_vec.clear();
132 ERR_FAIL_V_MSG(false, vformat("%s: refusing to allocate a negative count (%d).",
133 String(p_where), p_count));
134 }
135#if defined(TESTS_ENABLED)
136 // Placed AFTER the negative-count guard and BEFORE the resize so the injected run takes
137 // the same exit as a real allocation failure: output cleared, error emitted, false.
138 if (gs_vector_alloc_consume_forced_failure(p_where)) {
139 p_vec.clear();
140 ERR_FAIL_V_MSG(false,
141 vformat("%s: injected allocation failure (test seam); "
142 "leaving the output empty instead of writing out of bounds.",
143 String(p_where)));
144 }
145#endif
146 if (p_vec.resize((typename Vector<T>::Size)p_count) == OK) {
147 return true;
148 }
149 p_vec.clear();
150 ERR_FAIL_V_MSG(false,
151 vformat("%s: failed to allocate %d entries of %d bytes (%d bytes total); "
152 "leaving the output empty instead of writing out of bounds.",
153 String(p_where), p_count, (int64_t)sizeof(T),
154 p_count * (int64_t)sizeof(T)));
155}
