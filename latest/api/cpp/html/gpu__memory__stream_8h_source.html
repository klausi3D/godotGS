58 // #798 review round 3: BUFFER_UPLOADING alone does NOT mean "an upload is in flight".
59 // _get_next_write_buffer() flips a slot to BUFFER_UPLOADING to CLAIM it, and the actual
60 // buffer_update()/submit() happens later, so between those two points the slot is
61 // UPLOADING with upload_fence == 0. _wait_for_buffer_complete() runs lock-free from the
62 // render thread and treats fence == 0 as "already complete", so it would publish that
63 // never-written slot BUFFER_READY -- and get_current_gpu_buffer() selects purely by
64 // state, so the renderer then gets the slot's PREVIOUS GPU contents.
65 //
66 // This flag is the claim/submit distinction the state machine was missing: false from
67 // the moment the slot is claimed, true only once an upload has actually been submitted
68 // and the fence fields are written. _wait_for_buffer_complete() refuses to publish while
69 // it is false, which makes the failure cleanup in _stream_internal() race-free instead of
70 // merely narrow: the poller can no longer win, in either interleaving.
71 //
72 // Release/acquire, not relaxed: the store below is the release edge that publishes
73 // upload_fence / upload_submit_frame / upload_frame_delay (all plain scalars) to the
74 // lock-free poller, which acquires here before reading them.
75 std::atomic<bool> upload_submitted{false};
76 uint64_t frame_last_used = 0;

188 // that could realistically exhaust the allocator is rejected earlier by the

190 // `aligned_size > buffer.capacity` bail inside _upload_buffer_coalesced() is likewise
