17// Positional payload reads on a bounded reader pool
18// (docs/architecture/adr-beyond-vram-worlds.md §3.1, §3.2, §3.4 step 5; BV-08b).
19//
20// BV-08b shipped the service alone. Its first runtime caller is the paged-GSQ staged source
21// (BV-C5b, core/streaming_gsq_chunk_payload_source.h).
22//
23// Contract:
24//
25// - submit() never blocks and never waits for budget. Every byte of a request is charged
26// to max_bytes_in_flight from an accepted submit() until its completion is taken or it
27// is cancelled, so a consumer that stops taking completions stops further admission
28// and nothing piles up behind the readers. A caller that gets SUBMIT_BUSY skips the
29// request and asks again next frame, the same rule as run admission (I-2).
30// - A read is positional: a reader leases a handle exclusively, seeks and reads, so
31// concurrent reads of one file never share a cursor.
32// - Handles are pooled per path across readers. At most reader_count + max_idle_handles
33// are open at once; the least recently used idle handle closes first.
34// - cancel() is exact: once it returns true, that ticket is never delivered. A read
35// already running stops at its next slice boundary (read_slice_bytes) and keeps its
36// budget until then, because its buffer is still allocated. Its ticket can be submitted
37// again at once.
38// - A completion carries either every requested byte (error == OK) or none. A short read
39// is ERR_FILE_EOF, and the handle that saw a failure is closed rather than pooled.
40// - Tickets are opaque to the service and unique among live requests. Generation checks
41// (I-5) stay with the residency owner, which encodes the generation in the ticket.
42//
43// Threading: submit(), cancel(), cancel_and_wait(), stats(), poll_completion(),
44// wait_completion(), wait_ready() and release_handles() are safe from any thread.
45// start() and shutdown() belong to the owner,
46// who must not call anything else concurrently with destruction: shutdown() wakes and
47// waits out completion, ready and cancellation-drain waiters, but cannot protect a call that
48// starts after the object is gone. `mutex` guards every field declared after it; file
49// I/O runs outside it.
