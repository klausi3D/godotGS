9/*
10 * Module-owned StringNames whose lifetime must straddle module
11 * register/unregister so the engine's exit-time orphan StringName report
12 * (StringName::cleanup) does not surface them.
13 *
14 * Function-local `static const StringName s("...")` cache sites are easy
15 * to write but cannot be released — the StringName lives in static
16 * storage until program exit, which means its slot in the StringName
17 * table is occupied past the module's unregister window. Anything that
18 * references those slots from the other side (e.g. a Dictionary that has
19 * already been freed) shows up as `Orphan StringName: ... (total: N)`.
20 *
21 * This struct holds the small set of paths that were previously cached
22 * via function-local statics. register_types.cpp::
23 * initialize_gaussian_splatting_module() constructs the struct; the
24 * matching uninitialize() call drops it, releasing the StringNames
25 * cleanly so they leave the StringName table at unregister.
26 *
27 * See tests/ci/run_module_tests.py::_run_stringname_orphan_guard_step
28 * for the CI guard that asserts the orphan count stays bounded.
29 */
30
