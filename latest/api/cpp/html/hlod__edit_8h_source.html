4// ADR docs/architecture/adr-hlod-streaming.md section 14.5 (package F1): editable regions in a baked or paged HLOD
5// world.
6//
7// An edit replaces the splats of one or more LEAF nodes. It never modifies a snapshot, a world or a V4 file: it derives
8// a new immutable GaussianSplatHlodRuntimeData whose edited leaves carry their replacement payload in memory (an
9// overlay over the base, which keeps serving every unedited node, from RAM or from the V4 file) and whose ancestors
10// of those leaves are STALE (GaussianSplatHlodRuntimeData::EDIT_STALE). The selector (lod/hlod_runtime_selection.*)
11// never draws a stale node and never uses it as a fallback; it replaces it by its children, so until a rebake
12// (package F2) the edited region is drawn from the new leaf versions and the untouched siblings along the path.
13//
14// F1 edit rule (what is accepted, everything else is refused with a distinct status and changes nothing):
15// - only leaf nodes; at least one and at most kMaxEditedLeaves per transaction; at most 16,384 splats per leaf;
16// - every replacement splat is finite and stays inside the leaf's existing bounds (centre +- 3 sigma inside the AABB
17// and the bounding sphere), so no ancestor bound, radius or geometric error changes;
18// - a leaf may not become empty (removing a leaf changes the topology: deferred);
19// - the caller states the revision it edited from; a snapshot that moved on is refused (expected prior revision).
20//
21// Threading: pure CPU, no shared state; call from any thread. Positions are absolute float32, the leaf convention.
