50 // #862 coalescing latch. True from the moment a `changed` emission from the
51 // assigned GaussianSplatWorld has queued a deferred resubmit until that
52 // resubmit runs. Further emissions in the same frame fold into the pending
53 // run instead of queueing another one -- a single user-visible content write
54 // emits `changed` more than once (see _on_world_resource_changed()), and
55 // re-running the registration per emission would turn one property write into
56 // several render-thread round trips. It is also the re-entrancy guard: a
57 // `changed` emitted from inside the flush cannot nest a second registration.
58 //
59 // ATOMIC, not a plain bool, because the two accesses are not on the same
60 // thread. Resource::emit_changed() (core/io/resource.cpp:44-51) routes to
61 // ResourceLoader::resource_changed_emit() when a threaded load is running on a
62 // worker thread, and that calls the connected callable SYNCHRONOUSLY on the
63 // loader thread (core/io/resource_loader.cpp:965-974). So the arm can happen
64 // off the main thread while the disarm always happens on it. A plain
65 // read-then-write would be an unsynchronized read-modify-write on a shared
66 // object; the arm below uses exchange() so two concurrent emissions still
67 // queue exactly one flush.
68 std::atomic<bool> world_resource_resubmit_pending{ false };
