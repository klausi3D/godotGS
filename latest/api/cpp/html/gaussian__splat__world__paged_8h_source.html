4// ADR docs/architecture/adr-hlod-streaming.md section 14.4, package E1: the V4 paged HLOD package.
5//
6// V4 is a distinct, opt-in format identity (version word 4). It never reinterprets V3 bytes and the strict v1-v3
7// readers are untouched: select_header() still refuses version 4, and this file is the only reader of it.
8//
9// Layout (little endian, every offset and count a checked unsigned 64-bit quantity, every region page aligned):
10//
11// [0, 4096) header page: identity, counts, region extents, index digest, header digest
12// [4096, +index_bytes) index pages (64 KiB each): 255 fixed 256-byte node records per page, each page led by
13// a 64-byte header carrying its own SHA-256 so one page can be verified alone
14// [payload_offset, ...) one payload record per node, each starting on a 4096-byte boundary:
15// 64-byte record header + count * sizeof(Gaussian) + count * high_order * 12 bytes
16// [metadata_offset, ...) optional UTF-8 JSON dictionary (world metadata), digest in the header
17//
18// A node record repeats the v3 topology and adds what the runtime snapshot used to derive by scanning the whole
19// payload: the overlap footprint, the DC encoding, whether the node is DC-homogeneous and whether its centre
20// reconstructs its positions exactly (the "snapshot scan" D1 listed as the reason the CPU copy of the payload
21// stayed resident). With them the runtime needs no payload to describe a node; payloads are read on demand.
22//
23// Positions are stored node-relative exactly like the v3 gaussian section (leaf positions relative to the cell
24// centre); read_node_payload() hands the runtime the same absolute float32 leaf positions the resident load
25// produces, so a node packs bit-identically whichever way it was read.
26//
27// Integrity metadata never replaces semantic validation: every page and record is hashed AND its topology,
28// finiteness, bounds and metrics are re-derived and compared. Failures carry a distinct reason string.
