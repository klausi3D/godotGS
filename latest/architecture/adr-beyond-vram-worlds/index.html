    ADR: Worlds beyond VRAM — compressed streaming, chunk streaming and HLOD as one design¶

    • Status: proposed. Implementation follows the roadmap order in §10, and each code PR carries its own risk class. This record is a design only: it changes no code, and no build or GPU run backs it.
    • Date: 2026-11-04.
    • Risk: this document is R0 (docs/**). It is the design record that the R3 packages it schedules depend on (docs/governance/agentic-engineering.md). Those R3 packages are BV-01, BV-02, BV-03a/b, BV-05, BV-06a/b, BV-07, BV-08b, BV-09, BV-13a/b, BV-14, BV-C1a/b, BV-C3, BV-C4, BV-C5a, BV-C6, BV-C7, BV-16a/b/c, BV-17, BV-18a/b, BV-19, BV-20a–d, BV-21a/b, BV-26a, BV-27, BV-30, BV-31, BV-32, BV-33 (upstream engine), BV-34b and BV-35a–d (§10).
    • Base: 44836e1d6a5 (origin/master, the merge of #1293). Every file:line below was read at this commit.
    • Refs: #1131, #1053, #320, #1051, #54.
    • Related ADR: Hierarchical LOD for streamed splat worlds (cited below as "HLOD ADR"). Its §16 points here for Package G at scale.
    • New requirement (maintainer, 2026-11-03): a game must not ship hundreds of GB. Large worlds therefore use a compressed, streamable on-disk format, and so does the test world. Uncompressed data is kept only where it is needed: quality references, byte-identity proofs and one bounded early probe (D-13).
    • Paths are relative to modules/gaussian_splatting/ unless they start with docs/, tests/, .github/, drivers/ or servers/, or are marked "repo root". Short forms: world.cpp = core/gaussian_splat_world.cpp; publisher.cpp = renderer/resident_instance_contract_publisher.cpp; paged.cpp = io/gaussian_splat_world_paged.cpp.
    • Citations: ✓ means the cited lines were re-read at 44836e1d6a5 for this record (Appendix A). A citation without ✓ was carried from the design research and not re-read.
    • Labels: [M] measured (source named), [D] derived from cited constants, [E] estimate, UNVERIFIED not confirmed.
    • Naming: milestones are M1, M1c, M2, M3, M4, M5 everywhere. D-1's architectural steps are Steps A/B/C. Roadmap phases are P0–P6 (§10).

    1. Context and goals¶

    1.1 Problem¶

    GodotGS has never rendered a world larger than GPU memory. The largest stress tier is 2.5M splats (tests/runtime/test_gpu_streaming_stress.gd:69, tier_2_5m at :96-97 ✓). The 20M/50M/100M corridor stages are planned_unstaged (tests/runtime/open_world_chunked_asset_ladder.py:118-119, :194 ✓) and resident: the 20M corridor is an in-memory world merged from 800 instances of one asset (tests/examples/godot/test_project/scripts/benchmark_open_world_stage_contract.gd:44-79 ✓). The corridor lane has never produced a result: every reachable scheduled run of gaussian_production_gates.yml timed out before the lane's first frame (for example run 40298399722; Refs #1045) [M].

    Two partial systems exist:

    1. Chunk streaming (GaussianStreamingSystem + StagedFileChunkPayloadSource). It streams uncompressed plain v3 out of core. Its distance LOD saves no VRAM (#1053), it has per-frame O(N) residue (#320), its gate counters are stubs in optimized builds (D-5), and one buffer holds the atlas.
    2. HLOD (V4 paged packages, NodeResidency + HlodNodeStreamer). It streams nodes, but under pilot caps of 1,048,576 leaf splats, 1,572,864 payload splats, 32,768 nodes, 512 MiB GPU and 1 GiB CPU (core/gaussian_splat_hlod_runtime_data.h:14-18 ✓; world.cpp:1191-1194 ✓), plus a 2 GiB staging ceiling on the streamed atlas (renderer/resident_atlas_budget.h:36 ✓, applied through atlas_limit at publisher.cpp:1716 ✓). Its V4 writer needs a resident world. It is a second residency instance, which HLOD ADR §14 rules out (docs/architecture/adr-hlod-streaming.md:1076-1079 ✓).

    No streamable compressed format exists.

    • The only world compression (flag bit 4, kFlagCompressed, io/gaussian_splat_world_io.cpp:58 ✓) gzips the whole gaussian section as one blob. It is resident-only (:340-352 ✓) and bounded by INT32_MAX decompressed bytes (:65-81, :1573 ✓), about 14.9M splats [D].
    • Importer "compression" options change no stored bytes. They only set GaussianSplatAsset::compression_flags (io/resource_importer_spz.cpp:37-41 ✓, io/resource_importer_ply.cpp:136-146 ✓); outside the importers only the asset itself and editor code reference the field (grep ✓).
    • Disk today costs 292 B/splat for SH3 plain v3, so a 201M-splat world is 54.8 GiB [D].

    1.2 Goals¶

    # Goal Source
    G-a Render a physically stored, deterministic SH3 world several times larger than VRAM, on the 3080 runner and the 3090 workstation. maintainer requirement
    G-b Chunk streaming and HLOD form one design: one residency contract, one byte ledger, one page pool. maintainer requirement; HLOD ADR §14
    G-c Run the fly-through at the tuned settings: 4M visible cap, 400 m far plane, 4096 MB budget, 320 chunks. Production defaults are reported separately. maintainer requirement
    G-d Frame targets: 3080 p95 ≤ 25 ms and p99 ≤ 33.3 ms; 3090 p95 ≤ 16.7 ms and p99 ≤ 20 ms. Never loosened. §5.1 states plainly what reaching them takes, and §10 schedules calibration and gating for both devices. maintainer requirement
    G-e The out-of-core writer is a reusable io/ API, and it carries the page codec. maintainer requirement
    G-f Use an optimized build and a persistent world cache on the VM. The approved cache of about 60 GiB is sufficient; no VM disk growth is needed (§5.3). maintainer requirement
    G-g A shippable, compressed, streamable world format shared by plain chunks and V4 HLOD nodes: about 30–38 B/splat at SH3 [E], against 288–292 B today. new requirement
    G-h A path to HLOD ADR Package G: ≥ 100 km, ≥ 200M physical SH3 splats, about 1M drawn. docs/architecture/adr-hlod-streaming.md:1081-1088 ✓

    1.3 Non-goals¶

    • Real-scan beyond-VRAM content. It waits on #1294 and on tiled ingest.
    • Package F (editable regions).
    • Multi-package worlds (several world packages per scenario). Node instances are not a non-goal: they coexist with the world in the same frame per One route, many demand producers.
    • Retrained or neural compression (not decodable per page at streaming rates; see the compression survey in "External prior art").
    • Any change to S1b rules or to the #1290 waiver. The HLOD bake rule stays unchanged.
    • A GPU-resident compact layout (a stride-class atlas with shader decode). It is Package G stage 2 (P6).

    2. Decisions¶

    Each decision lists the alternatives considered and why they were rejected.

    D-1 One residency system, grown from NodeResidency, reached in Steps A → B → C¶

    Target. Each device has one ResidencyManager. It owns:

    • one segmented page pool: K ≥ 1 storage buffers, each ≤ min(device maxStorageBufferRange, UINT32_MAX), with 1,024-splat pages (renderer/hlod_node_streamer.h:39 ✓);
    • one byte ledger;
    • one upload and retirement path;
    • one PayloadReadService with codec decode.

    The unit is a run keyed by (asset_key, NodeKey, NodeVersion):

    • an HLOD node is a run of ≤ 16 pages;
    • a legacy chunk is a degenerate leaf node, a run of ≤ 64 pages.

    Selectors are separate demand producers: the HLOD ViewSet cut, legacy chunk visibility and the movable node instances (rows 1..N of one draw list, per One route, many demand producers); light views and extra camera views follow. The producer interface takes several producers per frame from the start, so Steps A and B do not harden around one producer.

    The seed is lod/hlod_node_residency. It already has whole-group admission, tickets with generations, retirement delay, protection, and eviction outside the closure → LRU → finest first (lod/hlod_node_residency.h:45-320 ✓). It does not yet scale: request() scans every node to cancel stale loads (lod/hlod_node_residency.cpp:285-290 ✓), stats() walks every node (:543-565 ✓), and evict_for collects and sorts every reclaimable node (:179-196 ✓).

    Threading. Every mutation of residency state belongs to the render thread, which is how the existing code is documented (lod/hlod_node_residency.h:35 ✓; renderer/hlod_node_streamer.h:20-21 ✓). The main thread submits only view specs. Reader, decode and pack workers hand results over through bounded single-producer/single-consumer queues. This is invariant I-11.

    Steps:

    • Step A (M1–M2). The first beyond-VRAM runs use today's chunk streamer, changed only for:
      • evidence and telemetry;
      • shared layers that survive: the ledger, PayloadReadService, the page codec, release counters, GPU timing;
      • blockers the probe proves.
    • Step B (M3–M4). HLOD at scale runs on the scaled NodeResidency. Its pool is sized by the streaming budget inside the device ledger (D-3).
    • Step C (M5). NodeResidency becomes the ResidencyManager with K segments. Primary chunk worlds become degenerate-node demand on it, and the chunk streamer's primary atlas, allocator and regulator are retired.
    Alternative Why rejected
    Two systems permanently Violates HLOD ADR §14. Two ledgers would compete for one device.
    Unify first An R3 rewrite would come before any data, and the pool would be designed blind.
    Segmented atlas in the chunk streamer Not needed at the tuned settings, and it would be built in the component Step C retires.
    Chunk streamer as the seed Its unit is a fixed 64k chunk with LOD as a draw count, it has the regulator ratchet, and it has no per-node generations.

    D-2 The world on disk: one content definition, GSQ-compressed in both containers¶

    One seeded, counter-hash, re-iterable generator (§6) defines the content. Every tier is stored compressed with the GSQ v1 page codec (D-12) in one or both containers:

    Encoding Tiers Role
    Plain v3 + paged GSQ chunks (new flag bit 7, D-12) T0, A Chunk route. Ships tree-less worlds. Flat arm from M1c onward.
    V4 + GSQ node records (codec field, D-12) T0, A, AB, AB-span HLOD route. Ships HLOD worlds. HLOD arm from M3 onward.
    Plain v3 uncompressed T0 (identity), T-ref (generated per run, transient), A once for the M1 probe (deleted at M1c) Quality references (the U arm), byte-identity proofs, and a codec-free scale probe (D-13).
    V4 uncompressed small identity worlds only (≤ 1M leaves) Byte-identity proofs (§4.5).

    Both compressed containers fit the approved cache together (§5.3). So the flat arm stays the chunk route on the runner for the whole program. No "leaves-only cut over V4" workaround and no disk-option choice is needed.

    Tier AB is a single V4 package (u32 counts suffice; about 80k nodes against a reader bound of 2^20, kMaxNodes at io/gaussian_splat_world_paged.h:57 ✓). It is never plain v3.

    AB alternative Why rejected
    SH2 HLOD ADR §14 requires SH3 capacity.
    Two plain v3 files Multi-world in one budget does not work: a second live world submission in a scenario is rejected (core/gaussian_splat_scene_director.cpp:2441-2449 ✓), and each renderer's streaming system takes the full budget. Chunk-only work would be retired at Step C.
    Lifting the 357.9M SH3 per-file cap (io/gaussian_splat_world_io.cpp:1617-1624 ✓) An R3 loader change for a route being converged. With paged GSQ chunks the SH section disappears, so the cap does not apply to the compressed container anyway (D-12).

    Generated worlds never enter res://. The importer HLOD-bakes non-empty plain worlds (io/resource_importer_gsplatworld.cpp:431 ✓), so worlds are loaded by absolute path.

    D-3 What replaces the 512 MiB cap, the 2 GiB staging ceiling on the streamed pool, and the other pilot caps¶

    Each replacement keeps fail-closed refusal with a distinct reason, has boundary tests at the bound and bound+1, and carries an explicit maintainer disposition in an R3 PR.

    Cap Replacement Scope / why this is not a loosening
    MAX_LEAVES 1,048,576 and MAX_PAYLOAD 1,572,864 Kept for resident captures (world.cpp:1290-1294 ✓). Removed from paged admission (world.cpp:1191-1194 ✓), which charges no payload (:1200-1201 ✓). They bound nothing on the paged route. The 1 GiB CPU_BYTE_LIMIT is kept.
    MAX_NODES 32,768 min(reader kMaxNodes = 2^20, the node count whose tables and per-view CutHistory workspace fit the CPU ledger) Derived. Still refused above the bound.
    GPU_BYTE_LIMIT 512 MiB Replaced only as the streamed page-budget term of hlod_stream_page_budget (renderer/resident_atlas_budget.h:118-120 ✓). It becomes the configured streaming budget (tuned 4096 MB, production 2048 MB) clamped by the device ledger. It is kept for whole-bundle admission, hlod_candidate_fits (publisher.cpp:1741, :1800 ✓), so medium scenes keep their current route. The 0.60 × device ledger (renderer/resident_atlas_budget.h:73-80 ✓) is kept.
    kResidentStagingCeilingBytes 2 GiB, through atlas_limit (renderer/resident_atlas_budget.h:36, :48-63 ✓; publisher.cpp:1716 ✓; used at :1779 ✓) The streamed pool is no longer clamped by it. The streamed pool is bounded by the streaming budget, the device ledger and the per-buffer API limit (≤ UINT32_MAX, or K segments after Step C). The 2 GiB ceiling stays for the resident whole-bundle route, where it bounds a single upload. Boundary tests sit at 2 GiB and 2 GiB + 1 page. The ceiling exists for one-shot uploads. A streamed pool uploads per run under the per-frame byte cap.
    Sort capacity = whole-tree leaf_count (publisher.cpp:1685 ✓) pow2(drawn budget) Only the drawn set is sorted.
    HLOD per-visible scratch sized from max_visible_splats (renderer/tile_renderer.cpp:4074-4114 ✓) Sized from the drawn budget. History and the SH cache stay indexed by pool record, so they scale with pool size (≈ 9 B × pool records). This is stated, not hidden. —
    Cut splat_budget = min(leaf_count, max_splats) (publisher.cpp:1657-1658 ✓, :2038 ✓) min(drawn_budget_splats, visible cap, pool records). This needs the new setting from BV-16c. —
    Offline job: 1 worker, 1 job Per-worker job contexts. Limits come per bucket from the frozen HLOD ADR §15.2 job manifest. —
    materialize_paged_resident fallback (nodes/gaussian_splat_world_3d.cpp:664-674 ✓) Refusal only above the resident limit. Worlds that fit RAM keep the warn-and-load fallback. Larger worlds would OOM today, so no working scene breaks. Closes the HLOD ADR §14.8 stop condition (silent whole-world materialization).
    A second HLOD view (multi-view) Refused with hlod_multiview_budget_undefined until per-view sub-budgets and a deterministic Desired merge exist (P6). This refusal is an interim only, and it keeps its typed reason; light views for splat shadow casters are not deferred (see P6). The drawn budget is a per-frame total. The benchmark has one view. This prevents closure starvation.

    D-4 Frame time: an honest model. HLOD caps the drawn count; the 3090 targets are at risk until F is measured¶

    Measured anchor [M] (3090, 1080p, Mip-NeRF 360 bicycle at about 2.04M visible, wg 512, optimized build; #539, measurement of 2026-10-09): frame ≈ 33 ms, overlap sort 13.9 ms. The rest of the split from the same runs — raster 8.9, emit/count/prefix/resolve 3.3, untimed ≈ 7 (cull, projection, depth pre-sort) and a present gap of 3–4 ms — is not recorded in the repository or an issue: UNVERIFIED.

    Model: mean GPU frame ≈ F + k·N, with N = drawn splats in millions; p95 ≈ 1.25 × mean [E]; the 3080 is ≈ 1.2× slower [E].

    • F ≈ 10.5 ms (present gap 3.5 + untimed 7) is the honest starting value. No measurement shows that #1180 or #1181 removes the untimed term. They may remove part of it, but that is UNVERIFIED.
    • k ≈ 8 ms/M for leaf-like content after #539, #1180 and #1181 [E].
    • Interior-heavy HLOD cuts cost more per splat, because merged interiors are larger and produce more overlap records (≈ 12 against ≤ 8 records per splat, §5.2) → k ≈ 12 ms/M [E].
    • k ≈ 5 ms/M is the optimistic benchmark-density case (UNVERIFIED).

    Predicted p95 at a 1.0M drawn budget [D from the model], as 3090 / 3080 in ms. "miss" marks a value above the target (3090 p95 16.7 ms; 3080 p95 25 ms):

    F \ k 5 8 12
    3.5 10.6 / 12.8 14.4 / 17.3 19.4 miss / 23.3
    7 15.0 / 18.0 18.8 miss / 22.5 23.8 miss / 28.5 miss
    10.5 19.4 miss / 23.3 23.1 miss / 27.8 miss 28.1 miss / 33.8 miss

    What this says plainly:

    • On today's evidence (F ≈ 10.5, interior k ≈ 12), neither target is met at 1.0M drawn.
    • 3090 p95 ≤ 16.7 ms needs a mean ≤ 13.4 ms. That requires both F ≤ ≈ 5 ms and k·N ≤ ≈ 8 ms. With interior k = 12 that means N ≤ ≈ 0.7M.
    • Reducing F means three things:
      1. timestamping the untimed passes (BV-04b);

      2. 1180 and #1181;¶

      3. finding and removing the 3–4 ms present gap, which is not yet attributed. Its cause is UNVERIFIED, and it has its own investigation item, BV-24b.
    • 3080 p95 ≤ 25 ms needs a mean ≤ 16.7 ms on the 3080, which is ≤ 13.9 ms in 3090 terms. That is the same order of condition, slightly looser.
    • The 4M visible cap as a drawn count misses both targets by about 2–3×. Under this design the 4M cap becomes a never-binding ceiling (G10h hard), and the gated workload is the HLOD drawn budget (§12 item 2).

    Decisions:

    1. The 4M visible cap stays as a ceiling that must never bind on the HLOD arm (G10h = 0, hard). That rules out #1131 there.

    2. New setting drawn_budget_splats (BV-16c, before the first HLOD run). It is frozen in the thresholds settings block by BV-26a before any HLOD-arm data exists. The rule is pre-registered now:

      N_frozen = the largest N ≤ 1.0M whose 3090 p95 the model predicts ≤ 16.7 ms, using F and k_interior measured at M1/M1c. F is measured on T0 at ≈ 0 drawn; k is fit from the sweep of 0.25/0.5/1/2/4M drawn, with records per splat per level measured on T0 V4.

      If N_frozen < 0.5M, the program stops and returns to the maintainer, because quality would be inadequate.

      This uses only flat-route and T0 data, never HLOD-arm results, so it is pre-registration. 3. τ, the SH read bands (SH3 < 50 m, SH1 50–150 m, SH0 > 150 m) and the codec bit depths are frozen in the same block. 4. Lowering the drawn budget, raising τ, moving the SH bands nearer or coarsening codec bits counts as a loosening of P1. The guard permits it only when G11q and Q-codec are hard and passing at the new value, with a maintainer waiver line (§8.4). 5. The frame targets gate the HLOD arm. The flat arm is printed against the same values, as information only (§12 item 3). 6. The 3090 is calibrated and gated on Tier AB (BV-30 → BV-32). The 3090 does not wait for Step C. 7. If M4 is not met (P1 hard and passing on the 3080 HLOD arm, and likewise on the 3090), M4 is reported "not met" with its numbers. The next actions are, in order: - measure F and k; - remove fixed cost (present gap, untimed passes); - reduce records per splat at the bake through an interior splat-size bound (with a quality gate); - the 144 B SH layout (BV-C8); - a compact GPU layout (P6).

      The targets never move.

    Alternative Why rejected
    4M drawn Predicted ≈ 35–45 ms.
    Lowering the visible cap Contradicts the maintainer's setting, and the cap would bind and flicker (#1131).
    Gating the flat arm It has holes (#1053) and is not the product route.
    A per-device drawn budget The two devices would show different content quality, and the evidence would not compare. Kept as a fallback only if the frozen rule yields < 0.5M (§12 item 2).

    D-5 Telemetry in optimized builds¶

    PackTelemetry::exchange_and_reset() returns {} without DEV_ENABLED (core/streaming_upload_pipeline.h:90, :222 ✓). So last_upload_chunks is always 0 (core/streaming_diagnostics_surface.cpp:244, :455 ✓).

    Precise effect:

    • upload_stalled needs queues > 0, upload_chunks_this_frame == 0 and loaded_this_frame == 0 (core/streaming_diagnostics_surface.cpp:530-533 ✓).
    • Only the broad forced-sync guard reads the constant (core/gaussian_streaming.cpp:4580-4585 ✓); the narrow guard (:4571-4576 ✓) does not.
    • Both can over-trip in release builds.

    Decision (BV-04a):

    • Gate-consumed counters become release-build atomics: upload chunks and bytes, read bytes, decode bytes, and read/decode/pack/upload latency histograms.
    • The 30-frame predicate is kept byte-for-byte; only its input is fixed.
    • Gates use an additional wall-clock stall metric.

    BV-04b adds GPU timing completeness:

    • binning validity;
    • per-frame-serial validity;
    • timestamps for the untimed passes (cull, projection, pre-sort, composite), needed to measure F;
    • records per splat per HLOD level.

    D-6 The regulator thrash ratchet¶

    _detect_thrashing (core/streaming_vram_regulator.cpp:416-429 ✓) triggers a 10 % max_chunks cut and lod_distance_multiplier × 1.1 up to 2.0 (:359-372 ✓), at most once per 30 frames (MIN_FRAMES_BETWEEN_ADJUSTMENTS, core/streaming_vram_regulator.h:99 ✓; checked at .cpp:348 ✓).

    Decisions:

    1. V7 freezes the effective budget, the chunk cap, lod_distance_multiplier, the drawn budget and τ in every measured frame. Any drift makes the run INVALID with reason settings_drifted.
    2. M1 is a probe. If any regulator event fires, its frame and quality numbers are published labelled settings_drifted, which is a finding and not a baseline.
    3. BV-08a lands before M1c. It measures thrash as visible-set refetch within a wall-clock window of K ms, never a frame count. It has a live negative control at two frame rates: a starved budget must trip it at both 60 and 200 fps. As built: K = 2000 ms, and it trips at a quarter of the chunk cap (at least 8) refetched inside the window.
    4. Production auto-regulation stays on. This changes production behaviour: the detector no longer fires on legitimate fly-through churn. It is a defect fix (false positives), proven by the negative control, so it is decided here rather than asked.

    D-7 V4 out-of-core write: spill-and-assemble in canonical BFS order, keeping every V4 writer refusal¶

    The format forces this two-step write: records are sequential in node order (paged.cpp:623-626 ✓) and content_generation hashes every body (:971-975 ✓). The validator needs only parent-before-child and contiguous child ranges (core/gaussian_splat_hlod_tree.cpp:109-110, :170-171 ✓). The in-core bake emits BFS (core/gaussian_splat_hlod_bake.cpp:549-564 ✓).

    Decision (BV-18a/b):

    1. Bodies are spilled per (bucket, depth) segment as GSQ-compressed pages (W14). The spill record carries the node metrics computed from the decoded runtime form: footprint, dc_encoding, homogeneous_dc, center_exact, and eps/radius.
    2. Topology fixes BFS order, offsets and content_generation from body digests over the stored bytes.

    D-8 Precision and the AB-span tier¶

    • The benchmark worlds stay within 2–4 km of the origin (ULP ≤ 0.49 mm [D]).
    • The chunk route is declared safe to ≤ 8 km, with a float_precision_risk telemetry flag beyond that.
    • GSQ positions are page-relative (D-12), so the codec adds no range limit. SPZ, by contrast, stores absolute 24-bit fixed point with 12 fractional bits, ±2,048 m [D] (thirdparty/spz/load-spz.cc:351-357 ✓).
    • At Step C, degenerate chunk nodes receive node-relative payloads plus per-draw camera offsets (HLOD ADR §14.3, package C2). No separate chunk-relative work is done.
    • AB-span is the HLOD ADR Package G capacity and precision tier. It holds Tier AB content (402,653,184 SH3) spread over ≥ 100 km, so it is 2.75× VRAM on the 3090 and satisfies V3 without exemption. It runs on the HLOD route only, after the origin-shift guard is removed on GPU evidence (P6).

    D-12 Compressed streaming format: GSQ v1 page codec, decoded on the CPU into today's GPU layout¶

    • Unit. A page is one plain-v3 chunk (≤ 65,536 splats) or one V4 node payload (≤ 16,384, kMaxNodeSplats, core/gaussian_splat_hlod_tree.h:45 ✓). It is split into 4,096-splat sub-blocks, each its own zstd frame, kept in the page's importance order so that a prefix is a valid sample.
    • Header. Each page has a 64 B header plus constants of ≤ 192 B: codec id, count, stored SH degree, the sub-block table, per-attribute dequant ranges, and a SHA-256 of the stored bytes.
    • Layout inside a sub-block. SoA, byte-planed, with positions delta-coded in the caller's order. The codec never reorders (io/gsq/gsq_codec.h:5-6 ✓, io/gsq/gsq_codec.cpp:559-565 ✓). Spatial order is the writer's job: BV-C3 sorts spatially (Morton) before encoding (decision 2026-11-07, #1347). How that sort coexists with the importance-ordered prefix (§6.2 "Per-chunk order") is fixed in BV-C3.
    • Page constants. The fields D-12 does not quantize (area, DC alpha, stroke age, brush axes, painterly_meta, render_meta) are stored once per page. The codec refuses a page whose splats differ in them with gsq_heterogeneous_field (io/gsq/gsq_codec.cpp:361-366, :434-438 ✓). Normals are the exception: they take per-splat planes when they differ (header flag bit 1). The BV-C3 page builder must group splats with equal page constants into pages. Any remaining failure must be visible, as an error or a counted fallback, never silent, and painterly content must stay encodable (decision 2026-11-07).
    • Quantization (pre-registered defaults, frozen in settings):
    Attribute Encoding
    Position u16×3 page-relative, or 3 × 21 bit when the step exceeds 0.25 mm
    Scale log scale, 3 × 10 bit per-page range
    Rotation smallest-three, 32 bit
    Opacity unorm16
    DC R11G11B10, per-page range
    SH bits 6/5/5 by band
    Normal only when flagged
    • Accepted error, conditional. Rotation error ≤ ≈ 0.28° (smallest-three, 3 × 10 bit plus a 2-bit index; bound and test in tests/test_gsq_codec.h:211-213 ✓) and SH stored as 1 B per coefficient (one byte plane per coefficient whatever the band's bit depth, io/gsq/gsq_codec.h:39 ✓) are accepted (decision 2026-11-07). The condition: the visual real-scan check of #1357 passes before GSQ becomes a default.
    • Size. Positions take 21 bits whenever 16 bits would be coarser than the 0.25 mm step, i.e. on any page wider than ≈ 16.4 m (io/gsq/gsq_codec.cpp:510 ✓), rounded to 3 B per axis. So 23 B of geometry plus DC and 45 B of SH3 give 68 B fixed width (io/gsq/gsq_codec.cpp:289-291 ✓; 65 B only on pages narrow enough for 16-bit positions), then ≈ 30–38 B after zstd [E] (BV-C2 measures it).
    • Decode location. The decode runs in the pack workers, straight into the existing 176 B PackedGaussian (renderer/gaussian_gpu_layout.h:340 ✓).
      • Shaders are unchanged and the async path is kept.
      • Godot's Compression::decompress serialises every caller on one global mutex and DCtx (repo root core/io/compression.cpp:45-48, :200-217 ✓). The codec therefore calls zstd directly with one ZSTD_DCtx per worker, using the module's existing zstd include path (the SPZ build environment, SCsub:20-21 ✓). That works with builtin zstd; system-zstd builds are UNVERIFIED.
    • Containers:
      • V4: a codec-id field. The header reserved word and record tail are zero today and enforced zero (paged.cpp:579-582, :771-775 ✓). The exact placement is fixed in BV-C4, and a test proves that old readers refuse it. GAUSSIAN_STRUCT_LAYOUT_VERSION keeps meaning the Gaussian struct layout and is not reused as a codec id. stored_bytes becomes the compressed size. The record SHA-256 covers the stored bytes.
      • Plain v3: a new flag bit 7 kFlagPagedChunks. Bits 0–5 are the plain flags and bit 6 is HLOD (io/gaussian_splat_world_format.h:15-16 ✓); unknown flags are refused by older readers (:34-35 ✓). Sections become page-aligned GSQ records. The chunk table gains offset, stored size, extent and digest. The index lists disappear (pages are chunks), which removes 4 B/splat on disk and 16 B/splat of RAM (four per-splat u32 index copies, for example core/streaming_asset_types.h:153-155 ✓). The SH section, and with it the 357.9M SH3 cap, does not exist in this container.
    • Determinism. Encoding uses integer-exact quantization with -ffp-contract=off-safe code. A cross-platform golden decoded digest is checked on Windows/MSVC and Linux/GCC.
    • Semantic read validation stays: counts, sizes, finite ranges, decoded positions within the page AABB plus 3σ, with gsq_* reasons.
    • Quality is gated by the U/C/S/D arms (Q-codec, §8.3): uncompressed, codec, SPZ control, degraded control.
    • The GPU SH layout of 144 B (15 SNORM10 words instead of 24 for SH ≤ 3; 9 words are dead today, renderer/gaussian_gpu_layout.h:312-319 ✓) is BV-C8, in P4, off the critical path. It fits 22 % more records in the same VRAM with no quality risk.
    Alternative Why rejected
    SPZ as the container One zstd frame per attribute for the whole scene gives no random access (thirdparty/spz/load-spz.cc:111-121 ✓), and positions are absolute ±2 km. Its quantizers are reused as test oracles and as the S control arm.
    Whole-section gzip (bit 4) Resident-only, ≤ 14.9M splats.
    A neural or retrained codec Not decodable per page at streaming rates.
    LZ4 or meshoptimizer LZ4 is not vendored (a new repo-root thirdparty/ dependency, R3); meshoptimizer is built by the separate modules/meshoptimizer, which creates a module dependency.

    D-13 One uncompressed scale probe (M1), then compressed everywhere¶

    • M1 runs Tier A uncompressed plain v3: 54.8 GiB, within the approved cache, with nothing else cached at the time (§5.3).
    • Why: it needs no codec work, so it delivers scale evidence (O(N) residue, RAM, the regulator, the first > 2 GiB single atlas buffer) about 3 weeks earlier. It also separates scale effects from codec effects. U-versus-C on the same route at scale is the confound control for disk throughput and pack CPU.
    • Then: the file is deleted when compressed Tier A is primed. M1c is the first compressed run, and every gated run is compressed.
    • No code is built only for M1: the uncompressed writer path is needed for identity proofs and references anyway.

    D-14 Cold-cache method¶

    A compressed Tier A of about 7 GiB fits in the 24 GB page cache, so cold runs must be produced and proven, not assumed.

    1. After generation, and after every per-run verify, fdatasync and then posix_fadvise(POSIX_FADV_DONTNEED) on every world file. This needs no privilege for one's own clean pages. Alternatively, verify with O_DIRECT.
    2. Residency check: mincore() through Python mmap + ctypes (no root needed) must show ≤ 1 % of world pages resident before a cold pass. Otherwise the run is INVALID with reason cache_warm.
    3. V10: on cold segments, /proc/<pid>/io read_bytes ≥ 0.9 × the manifest's expected unique stored bytes. Otherwise the run is INVALID with reason cache_warm.
    4. Host cache. O_DIRECT throughput on a never-read region is compared against a re-read. If the host caches the VM disk, every cold result carries host_cache: present, and "cold" means guest-cold only. G5 and G6t verdicts carry that label.
    5. A warm pass is reported separately and never merged with the cold one.

    3.4 Per-frame data flow (render thread)¶

    1. begin_frame. Process completed upload tickets:

      • generation check;
      • a run becomes RESIDENT once its upload command has been recorded ahead of this frame's draws;
      • publish resident_mask.

      Freed pages are reused only after the frame-delay retirement (frames in flight). That delay gates reuse, not visibility. 2. Selection over resident_mask produces Drawn (a complete cut), Desired (missing children of blocked refinements, by e·b) and Keep. It is monotone under caps and costs O(visited log visited). 3. Protection of the closure (I-3). 4. Requests. Per-frame caps on request count, eviction count and upload bytes ≤ staging ring / frames in flight. Each request: ledger check, eviction outside the closure, skip if nothing fits, ticket → PayloadReadService, and cancellation of stale tickets. 5. Workers. Positional read of the compressed page (≈ 1.5–1.9 MB per 49k chunk, ≈ 0.5 MB per 16k node [E]). SHA-256 check of the stored bytes, which costs ≈ 8× less CPU than today's uncompressed record hash (measured at M3). GSQ decode and pack into 176 B. Bounded ready queue. Upload into the run. 6. Draw list in cut order, then the renderer. 7. Telemetry to the frame trace.

    Coupling. Cut and residency interact only through resident_mask, the Desired order and the closure. On the HLOD arm a missing child keeps its parent drawn, so there are no holes; starvation shows as coarser frames and a slower settle. On the flat arm a missing chunk is a hole.

    7.3 Passes¶

    1. Controls first (§8.5). Each asserts a specific expected (gate, verdict, reason) tuple. The run is INVALID only when a control's observed tuple differs from its expected tuple. That covers:
    2. a wrong verdict or a wrong reason;

processes, scores at full resolution with ROI, and deletes the T-ref.

    8. Acceptance gates¶

    8.1 Principles¶

    • Verdicts: PASS, FAIL, INVALID, VOID (contention, exit 75) and NOT_RUN. There is no PENDING status. A gate whose prerequisite has not landed is absent from the thresholds file. It is added when the prerequisite lands, which is a tightening. The verdict module maps any unknown status to INVALID.
    • Two gate classes:
      • Correctness gates are hard from their first run.
      • Statistical gates have pre-registered fixed values, are report-only during calibration, and are promoted once if every calibration run passes. Promotion is one-way. The guard fails any hard → report-only change.
    • Timing and image-quality gates are statistical. Their values are fixed now.

    8.4 Thresholds file and the no-loosening guard¶

    tests/runtime/flythrough/flythrough_thresholds.json freezes, per gate:

    • value, op, class, arm, tier, source_field;
    • window definition, exclusions, percentile method (time-weighted, nearest-rank).

    It also freezes the following globals:

    • path_sha256;
    • generator_params_sha;
    • min_vram_ratio;
    • world digests (after the first prime);
    • settings:
      • the four tuned settings;
      • drawn_budget_splats, τ, SH bands;
      • codec params;
      • reference method (slab count, noise-floor method).

    tests/ci/check_flythrough_thresholds.py compares against the immutable base (GS_PR_BASE_SHA / GITHUB_BASE_REF, then origin/master, never HEAD). It fails on any of:

    • a loosened value;
    • a removed key, tier or gate;
    • a changed op, arm, window, exclusion, percentile method or source_field;
    • any hard → statistical or report-only change;
    • min_vram_ratio lowered;
    • path_sha256 or generator_params_sha changed without an accompanying world re-prime and gate re-calibration record;
    • non-finite values;
    • an unresolvable base;
    • any settings edit outside the allowlist.

    The allowlist is a direction table: an edit may only increase work or fidelity:

    • drawn budget ↑;
    • τ ↓;
    • SH bands farther;
    • codec bits ↑;
    • visible cap, far plane and chunk count are frozen (maintainer decisions).

    An edit in the work-reducing direction is permitted only when G11q and Q-codec are hard and passing at the new value, and a waiver line (maintainer, date, reason, evidence URL) is present.

    The tightening rule applies only to the non-user statistical gates (G5, G6, G6t, G14, G15, G11, G13, G11q, Q-codec). It is operator-aware, keyed on each gate's frozen op, and it can only move a threshold in the stricter direction:

    • Upper-bound gates (op is ≤: G5, G6, G6t, G14, G15): new = min(old, calibrated p95 × 1.15). The value never rises.
    • Lower-bound gates (op is ≥: G11, G13, G11q, and every Q-codec row, including the negative ΔPSNR/ΔSSIM floors): new = max(old, calibrated p5 − m). Here m ≥ 0 is a per-gate absolute margin in the gate's own unit (dB, SSIM). m is pre-registered in the thresholds file before calibration, and it is frozen like every other guarded field. The value never falls. A multiplicative margin is never applied to a floor, because on a negative delta it loosens. Example: −0.20 dB × 1.15 = −0.23 dB.
    • Proposals in the wrong direction: if a calibrated proposal would move a threshold looser (min/max leaves old), it is recorded in the calibration record and not applied. The no-loosening guard rejects any thresholds diff in which an ≤ value rises or a ≥ value falls. This holds whatever produced the diff.

    P1 values are the maintainer's targets and are never auto-tightened.

    The guard, not the risk class, is the control: the class itself is not a failure condition (docs/governance/agentic-engineering.md:184-185 ✓). The guard is wired into run_module_tests.py --guard-only, which runs in the required agentic-pr-gate. On schedule and dispatch the base equals HEAD, so the guard is vacuous there and is documented as informational. Mutation proofs:

    • raise a value;
    • delete a key;
    • demote a class;
    • change an arm;
    • edit drawn_budget down without a waiver;
    • use a bogus base;
    • delete the wiring.

    Each must turn the guard red.

    BV-PRIO (added after M1, run 42375402519). C0, C1, C6 and C7 never settled in either pass. The strict frustum needs 233–258 chunks at those poses and the cap is 320, but the route's needed set was the frustum with chunk_frustum_padding 1.5: 420–489 chunks. At each of the four poses needed_unserved_chunks is exactly that set minus the cap (100, 169, 121, 100); the four poses that settled have a padded set ≤ 260. Nothing told padding from demand, so:

    • near padding chunks were admitted before far frustum chunks;
    • the padded set could never be served, so missing chunks = 0 (§7.3) could not become true;
    • each load evicted another needed chunk for ever: 80–86 uploads/s at a static camera, 53 % of all M1 uploads (23,407 of 44,060) fell in settle waits.

    Decision: a chunk is needed when it is inside the frustum without the padding and inside the load distance. Needed chunks rank first at admission and last at eviction. A padding chunk draws when resident but is not demand: it and prefetch take free capacity only (off-screen victims are free capacity), never evict a needed chunk or each other, and any needed load displaces them. needed_chunks, needed_unserved_chunks, and through them the §7.3 settle, now count the needed set, which is the set §6.4 ground truth computes. A needed set larger than the cap still evicts itself; the BV-08a detector reports that as thrash.

    12. Decisions put to the maintainer¶

    These are the questions this design put to the maintainer, with the recommendation given at the time. The answers are recorded in "User decisions recorded 2026-11-03" below and are binding. Everything else is decided above with reasons: the codec scope (D-12), the bit depths (frozen, pre-registered and measured), the plain route (D-12: bit 7), the codec thresholds (Q-codec values pre-registered), uncompressed Tier A only for M1 (D-13), the 144 B layout in P4 with the compact layout in P6, cold-cache semantics (D-14), and the regulator fix (D-6). Disk: no VM growth and no cache increase are needed.

    1. Which binary the gated frame-time numbers come from.
      • Recommendation: template_release optimize=speed_trace dev_build=no running an exported pack, from BV-27, before any P1 calibration. The editor+tests binary stays the producer and the early probe binary, labelled as such.
      • Cost: a second build (≈ 25–45 min cold) and an export step per run.
      • Alternative: gate the editor binary and disclose that the numbers are editor-target numbers.
    2. The gated workload is an HLOD drawn budget, not the 4M visible cap.
      • At 4M drawn, the model predicts both targets missed by about 2–3×.
      • Proposal: the 4M cap becomes a never-binding ceiling (hard gate), and P1 is gated at drawn_budget_splats = the largest N ≤ 1.0M that the model, fed with M1-measured F and k, predicts meets 3090 p95 ≤ 16.7 ms. The value is frozen before any HLOD data.
      • If that N < 0.5M, the program stops and asks the maintainer again. The options then would be per-device budgets or accepting a 3090 miss; the targets themselves are never changed by the program.
      • Recommendation: approve.
    3. The frame targets gate the HLOD arm only. The flat chunk arm is printed against the same numbers for information.
      • Recommendation: yes. The flat arm cannot meet them by construction: prefix LOD, holes, up to 4M drawn.
    4. 3090 runs on the maintainer's workstation. This means:
      • about 9 runs × ≈ 1.5 h (5 calibration plus about one per milestone);
      • ≈ 40–60 GB of the 93 GB free on the workstation's data drive;
      • the maintainer's GPG key to sign each bundle (§9.3).
      • Recommendation: yes. Without it the 3090 targets remain unevidenced and M4 can be met only for the 3080.
    5. Shipping path for real content. Should PLY/SPZ imports write GSQ worlds?
      • Doing so bumps the importer format versions and forces a re-import of every project.
      • Recommendation: an opt-in importer option in P6, made default only after Q-codec is hard and passing on real scans.
      • Until then, shipped large worlds come from the io/ writer or converter path.
    6. Maintainer disposition for the HLOD cap replacements (D-3): the streamed 512 MiB term, the streamed 2 GiB staging term, paged leaf/payload caps, node bound, sort sizing, refusal above the resident limit.
      • Recommendation: approve the policy once, here, so that BV-16a/b/c and BV-17 carry a routine disposition line. Device-wide limits (0.60 ledger, 1 GiB CPU) and the resident-route caps stay unchanged.

    Release-gate integration moves to M4 and is not a decision now.
