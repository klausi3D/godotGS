    ADR: One route, many demand producers — the world and node instances in one frame¶

    • Status: Accepted (maintainer decisions, 2026-11-04). This record adopts #788 Option 2 ("genuine per-submission routing, accepted as target, deferred") as the direction and specifies how it is reached on the HLOD route first. Acceptance of this design does not establish implementation or runtime acceptance; the code PRs in §7 carry their own evidence.
    • Status update (2026-11-10): §12 adds the route retirement decision (D-2): one route, and the chunk-streaming route and the legacy composite are deleted. See Owner decision (D-2).
    • Status update (2026-11-11): §12.6 records the owner's acceptance of Option D as the target architecture of the one route: NodeResidency is its single residency core, and tree-less worlds reach it through an automatically built tree. See Owner decision (Option D).
    • Date: 2026-11-04.
    • Risk: this document is R0 (docs/**). The implementation PRs it schedules are R2 (modules/gaussian_splatting/renderer/**, and the director changes that alter what the renderer draws, which are R2 by design). The pick API (a bound method) and the runtime-profile scenario (tests/runtime/run_runtime_validation.py) are R3. The automatic-route PR changes existing scene behaviour and is classed R3 (public behaviour/compatibility, docs/governance/agentic-engineering.md).
    • Refs: #788, #855, #1131, #1095, #1163.
    • Related ADRs: Single route per frame: world/instance node coexistence (#788, "the #788 ADR"); Hierarchical LOD for streamed splat worlds ("HLOD ADR"), §6.9 and §14; Worlds beyond VRAM ("BV ADR"); Resident instanced contract.
    • Base: 992cb8eb733 (origin/master). Module code is identical between 44836e1d6a5 (the merge of #1293) and 992cb8eb733 (git diff --stat 44836e1d6a5 992cb8eb733 -- modules/ is empty), so every file:line below holds at both. Each one was re-read at 992cb8eb733 for this record.
    • Paths are relative to modules/gaussian_splatting/ unless they start with docs/, tests/ or modules/ (repo root). publisher.cpp = renderer/resident_instance_contract_publisher.cpp; director.cpp = core/gaussian_splat_scene_director.cpp.
    • Evidence status: every status in this record comes from reading code, git history and issue state. No status rests on a GPU run. Claims that need a run are marked UNVERIFIED.

    1. Problem¶

    GodotGS is for making video games. A game frame holds a large streamed world, static objects, movable objects, interactive objects, lights and shadows at the same time. Today no route draws a GaussianSplatWorld3D and a GaussianSplatNode3D in the same frame.

    1.1 The world row exists only without node instances¶

    GaussianSplatSceneDirector::build_instance_buffer_for_renderer() emits the world's identity row (asset 0) only when world->instance_store.is_empty() (director.cpp:1744). The grading rows repeat the rule (:1967), and so does the grading generation (:2114). InstanceStore::is_empty() is instances.is_empty() (core/gaussian_splat_scene_director.h:494), so a hidden node removes the world too: the row loop skips hidden records (director.cpp:1804), the empty test does not.

    Both canonical routes consume this list:

    • Resident canonical. The publisher packs the world's data into the atlas at dense id 0 (publisher.cpp:304-314), but no row references it, so its VRAM is spent and nothing draws it. The bootstrap row is suppressed whenever a world submission exists (publisher.cpp:442-449).
    • Chunk streaming. The streaming orchestrator builds its rows from the same function (renderer/render_streaming_orchestrator.cpp:801-803). A node whose asset has no streaming slot falls back to the primary dense id (:160-164), so it draws world data at the node's transform.

    1.2 The HLOD route is exclusive and single-instance¶

    • has_exclusive_hlod_world_submission() requires instance_store.is_empty() plus an active submission by the owner (director.cpp:3045-3049).
    • The publisher refuses the route with hlod_not_exclusive_world_submission or hlod_paged_not_exclusive_world_submission (publisher.cpp:1628-1638). The same predicate invalidates a prepared bundle (:1380), names hlod_exclusive_submission_lost (:1480-1481), and is reported per frame under the mislabelled key deformation_or_instance_domain (:1930-1932).
    • The bundle build requires exactly one instance and one grading row (instances.size() != 1 || grading.size() != 1 → hlod_identity_shim_unavailable, publisher.cpp:1722). The bundle is built from instances[0] and grading[0] (:1817-1818) with instance_count = 1 (:1317). Every draw record names GPU instance 0 (make_drawn_node(0u, …), :2196).
    • Any instance-generation change invalidates the prepared bundle (:1382), and a transform-only update bumps that generation (director.cpp:1279). A moving node would rebuild the bundle every frame.
    • A V4 paged world has no canonical payload. When the HLOD route does not serve, the frame is skipped with hlod_paged_route_unavailable or the route's reason (publisher.cpp:279-285). One node in the scene makes a paged world draw nothing, the node included.

    1.3 What is already multi-instance¶

    The GPU side and the selector do not assume one instance:

    • DrawnNodeGPU { instance_id, chunk_id, … } (shaders/includes/gs_instance_layout.glsl:108-112); the binning pass checks selected.instance_id != splat_ref.instance_id (shaders/tile_binning.glsl:878-879).
    • The camera-relative frame applies the instance's rotation and uniform scale and takes T from the per-draw offset (shaders/includes/gs_camera_relative.glsl:5-11, :43-53; shaders/tile_binning.glsl:900-904).
    • The host forms camera_offset = R s c + T − camera in double (core/gaussian_splat_world_frame.h:58-73).
    • SnapshotAsset and SnapshotInstance carry per-asset payload bytes charged once per asset, precise placements and per-instance caps under one physical budget (lod/hlod_view_set.h:9-19, :71-93).

    Only the CPU publisher and the director's row builder are wired to one row.

    3. Decisions (maintainer, 2026-11-04)¶

    These decisions are binding.

    1. Product rule. GodotGS is for making video games. A large streamed world, static objects, dynamic or movable single objects, interactive objects, lighting and shadows must all work in the same frame. A feature that works only with an exclusive world, with a single instance or with no other nodes is not acceptable. Any such precondition is a blocker that goes to the maintainer before it is built.
    2. One route, many demand producers is the target. #788 Option 2 is adopted as the direction. The HLOD world cut and the node instances share one draw list, one depth sort and one byte ledger per view. Instances join the HLOD route as rows 1..N.
    3. Budget. Visible objects reserve their share first, and the world keeps a fixed minimum share (floor). If the objects would exceed their share, that is an explicit refusal with a distinct reason and a counter. It is never a silent cut.
    4. #855 ordering. The "#855 first" constraint of #788 §5.2(3) is waived for the HLOD route only. #855 (the chunk route) is fixed in parallel as follow-up F1.
    5. Automatic route. A world with an HLOD snapshot takes the HLOD route automatically, together with the objects. This is a behaviour change and lands in its own PR with a release note.
    6. Real splat shadow casters now, not proxy meshes (#1095, #1163).

    4. Design¶

    4.1 Producers, rows and the draw list¶

    Per view there is one draw list (DrawnNodeGPU[]), one sort and one byte ledger. Producers write records into the same relative bundle, which then runs the existing depth, sort, binning and raster chain once.

    • P0, the world cut. The existing ViewSet selection over the HLOD tree. Row 0 is the world's identity row (asset 0).
    • P1..PN, the node instances. One row per visible GaussianSplatNode3D, built by the director exactly as today's node loop does, with the world row prepended. In PR1b each instance is drawn whole: one draw record per chunk of its asset. F2 puts instances under HLOD.
    • Record order. World records keep NodeKey order; instance records follow, ordered by (row, chunk). Ties stay deterministic by (instance_key, NodeKey) (BV ADR I-10).
    • Assets. One AssetMetaGPU and one packed payload per distinct asset. Instances of one asset share its payload and pay one row each.
    • build_instance_buffer_for_renderer() is left unchanged by the HLOD PRs, so the canonical routes keep their behaviour until F1. The HLOD route gets its own row builder (world row + node rows + parallel 64-bit asset ids + precise placements).

    4.2 Per-row transforms in the camera-relative frame¶

    • World records: unchanged. The ViewSet forms DrawRecord::camera_offset against snapshot.origin and its revision.
    • Instance records: an instance asset's payload is asset-local, so c = 0 and the offset is T − camera, computed in double with PrecisePlacement::from_frame_transform(node global transform, snapshot.origin) and camera_relative_offset(placement, 0, camera) (core/gaussian_splat_world_frame.h:58-73). It is computed once per instance per view and copied to each of that instance's records.
    • R and s come from the instance row, which the shaders already read. The row's translation is ignored in relative mode (shaders/tile_binning.glsl:900-904).
    • Origin shift: the hlod_world_origin_shifted guard stays (publisher.cpp:2076). Instance offsets use the same snapshot.origin_revision as world offsets, so the two never mix revisions.
    • Non-uniform scale stays reduced to the maximum axis, as on every route today. It is not new.

    4.3 Asset-set generation and row generation are separate¶

    Today one instance generation decides whether the prepared bundle is current (publisher.cpp:1382), and a transform update bumps it (director.cpp:1279). The design splits it:

    • Asset-set generation (get_instance_asset_generation_for_renderer, director.cpp:2185): adding or removing an asset changes the packed content and still rebuilds the bundle.
    • Row generation: transform, visibility and grading changes re-upload the rows only (N × row size). Offsets are recomputed every view, as world offsets already are.

    Moving nodes therefore cause no rebuild. The resident publisher already makes the same split between its atlas and instance generations.

    4.4 Readiness: an idle world never hides the objects¶

    Today a streamed world whose cut is not ready publishes an idle bundle with draw count 0 (publisher.cpp:1443-1462). In the target, idle means world records = 0, instance records still drawn. The whole-tree canonical bundle carries the instance assets and rows too. A world that is loading never blanks the objects, and BV ADR I-4 (complete-or-nothing) holds per producer.

    4.5 Budget rule¶

    • One device ledger. Instance payload, metadata, rows and the extra splat-ref and draw-entry capacity are added to hlod_bundle_bytes (publisher.cpp:1206), so hlod_candidate_fits charges them before allocation (:1741, :1800). Shared payload is charged once per distinct asset. On streamed and paged worlds the instance region sits at the tail of the relative atlas; its bytes enter the fixed bytes of hlod_stream_page_budget (:1774-1779), so the page budget shrinks and the ledger is never exceeded.
    • Per-view caps. Today the world cut gets min(leaf_count, max_splats) (:1657-1658, :2038). The target splits the view caps (splats, draw records, overlap records):
    • The world floor F is a fixed minimum share of each cap that the world keeps.
    • The object share is caps − F. Visible objects reserve their need R from it first, computed on the CPU before selection.
    • The world cut gets caps − R (never less than F) through spec.caps; the ViewSet honours it or returns NOT_ADMITTED with its existing reason.
    • If R > caps − F, objects are admitted in a deterministic order until the object share is used up. The order is screen-space importance; ties are broken by the node's stable instance id, so the same view always admits the same objects and no flicker can result (#1131).
      • Each object that is not admitted is refused explicitly, as a whole object, never as a partial draw. Its reason is hlod_instance_reserve_exceeds_object_share.
      • Refusals are counted by hlod_instance_refused_objects (per frame) and hlod_instance_reserve_refusal_frames.
      • The node can query its own refusal state, so gameplay code can react.
      • The world keeps its floor F and keeps drawing.
      • Objects are never dropped as a group just because one of them does not fit: objects come first (decision 3). Stated per-object priorities that override the importance order are F3.
    • The sort capacity is max(leaf_count, capacity) (:1685) plus the instance capacity.
    • The value of F is set and justified in PR1b. Exposing it as a project setting is a settings change and is R3 (F3); PR1b may ship it as a named constant.

    4.6 Domains that stay refused on the HLOD route¶

    Wind and sphere effectors (publisher.cpp:1517-1524, :1930-1932), painterly, the shadow instance filter, and non-main or multi-view passes (:1923-1926) stay refused, each with its typed reason. The mislabel at :1930-1932 is fixed: loss of exclusivity no longer exists, and effectors keep their own key. Each domain is lifted in its own PR (F5). Under decision 1, every such refusal is a listed gap in §8, not an accepted precondition.

    4.7 Automatic route¶

    Today HLOD runs only on the resident route. Under route_policy = streaming the plan records hlod_route_policy_chunk_streaming (renderer/gaussian_splat_renderer.cpp:1700-1705). The runtime cut is opt-in (rendering/gaussian_splatting/lod/hlod_runtime_cut_enabled, default false, lod/lod_config.cpp:400), and the project default route_policy is streaming (core/gaussian_splat_manager.cpp:1008). Under decision 5, a world that carries an HLOD snapshot takes the HLOD route with its objects without either setting. That PR states in its release note how the two settings behave afterwards (opt-out or removal).

    5. Alternatives rejected¶

    Alternative Why rejected
    (b) Merge the HLOD cut into the resident/chunk canonical route The canonical route uses absolute float positions, the non-relative shader permutation and 8 B VisibleChunkRefGPU with no per-draw offset. Drawing a cut there means adding DrawnNodeGPU and the camera-relative frame to it, which re-implements the HLOD route inside it. It would also need page-managed residency in an atlas packed whole per asset. A V4 paged world has no canonical payload at all (publisher.cpp:279-285). The whole-tree canonical bundle loses the cut, the parents and the 100 km frame.
    (c) Two routes per frame, composited #788 §5.2(2): with one colour and one depth per pixel, independent sorts cannot order transparent splats across routes. It contradicts "one depth sort".
    Keep exclusivity and warn (#788 Option 1 only) Violates decision 1. A warning names the defect; it does not draw the scene. Option 1 stays useful as a diagnostic (GR-21).
    Hard-reject world + nodes (#788 Option 3) Rejected in #788 §5.3, and it contradicts decision 1.
    Proxy meshes as splat shadow casters Overruled by decision 6.
    Instances take everything first, the world gets the rest The world could be starved to nothing by objects. Decision 3 gives the world a floor and refuses the excess explicitly.
    #855 first for every route Waived for the HLOD route by decision 4: #855 concerns the chunk route's cull, not the HLOD path, and keeping the order would leave paged worlds blank with any node.

    6. Tests that pin today's exclusivity¶

    They change honestly; none is weakened.

    • tests/runtime/test_hlod_resident_main_view.gd adds and removes a transient GaussianSplatNode3D and expects a rebuild. It stays valid, because adding a node changes the asset set. Its comment calling the world "exclusive" changes, and a sibling case asserts that a transform-only change does not rebuild.
    • modules/gaussian_splatting/tests/test_scene_director_submission_scaffolding.h:2235 ("World submission produces identity instance in build_instance_buffer_for_renderer") pins the world-only row of build_instance_buffer_for_renderer. It is unchanged until F1.
    • qa_stream_multi_asset.tscn stays quarantined (tests/examples/godot/test_project/scripts/qa_test_runner.gd:78-80) until F1. The HLOD PRs do not prove chunk-route coexistence.
    • The reason keys hlod_not_exclusive_world_submission, hlod_paged_not_exclusive_world_submission, hlod_exclusive_submission_lost and hlod_identity_shim_unavailable are removed with their code paths in PR1b. The HLOD ADR lists the first one among the edit-route causes (§14.5.1); PR1b updates that list.

    9. GS-COMBINED-1 hard gate¶

    GS-COMBINED-1 is the scene a game uses. It is the acceptance scene for decision 1. Its harness and lane are R3 (gate machinery and workflow) and land as their own PR; this section is the spec.

    9.1 Lane¶

    • It runs on PR, push and schedule, split into two jobs so that the required status and the runner trust boundary both hold:
    • The trusted GPU execution job runs on the 3080 runner and carries the per-job fork guard (github.event_name != 'pull_request' || head.repo.full_name == github.repository). Untrusted fork code never runs on the persistent self-hosted runner (docs/governance/review-policy.md:59-66, the same guard as .github/workflows/release_ci_runtime.yml:43). A fork PR is validated only after a maintainer moves it to a same-repository branch.
    • The required status job runs on a hosted runner. It needs: the execution job and has the job-level condition if: ${{ always() }} and no other. A job with needs: is skipped when its dependency is skipped or fails, unless its job-level condition overrides that, and a skipped job would satisfy a required check. A step-level if: always() cannot start a skipped job. always() is the only job-level condition allowed here, because it can never skip the job. Inside the job, a step reads needs.<execution job>.result and is fail-closed. It passes only if that result is success on this head. If the execution job is skipped, as for a fork PR, the status fails with the reason gs_combined_requires_trusted_branch. If it is cancelled or fails, the status fails too.
    • Optimized build with tests enabled.
    • Variant A: a chunk-streamed plain world. Variant B: the same content as a V4 paged HLOD world. Both run on every trigger, pilot scale first.
    • Deterministic: fixed seed, fixed camera spline, 600 frames, fixed timestep, pinned settings file, cold cache for variant B.

    9.2 Content¶

    • The world (≥ 1 km², SH3), from the BV generator.
    • 32 GaussianSplatNode3D (4 assets × 8 instances) on scripted paths, at least 8 interpenetrating world geometry, each with 16 tracer splats at known positions.
    • One designated picked object under a scripted cursor ray.
    • One skinned mesh character in front of, inside and behind world foliage.
    • One directional light with shadows and 4 omni lights with shadows.
    • Shadow receivers: a mesh floor under a splat object, splat ground under a mesh, a splat object over the splat world.

    9.3 Assertions (every frame unless stated)¶

The harness asserts that it ran 600 frames and that each assertion family evaluated on ≥ 590 frames, so a run that executes nothing fails.

    9.4 Forcing controls (each must make the gate fail, in the same job)¶

    1. Restore instance_store.is_empty() exclusivity → A1 or A3 fails.
    2. Drop the objects from the sort input (debug flag) → A2 or A4 fails.
    3. Disable the shadow caster pass → S1 fails.
    4. Delete the stats key object_drawn_splats → the fail-closed rule fails.
    5. Freeze one pass timestamp for one frame → the P-family validity check fails.
    6. Make pick return no hit → A6 fails.

    A family whose subject is not built yet (for example picking before F4) fails; it does not skip. Until every family passes, GS-COMBINED-1 reports which requirements are not met. That is the honest status of decision 1.

    12.1 Problem¶

    Sections 1 to 11 decide that the world and node instances share one draw list on the HLOD route. They do not decide whether the other routes stay. Today a frame can take one of these paths:

    • the resident canonical route;
    • the chunk-streaming route (renderer/render_streaming_orchestrator.cpp, core/gaussian_streaming.cpp, core/streaming_global_atlas_registry.cpp), the project default under rendering/gaussian_splatting/streaming/route_policy;
    • the HLOD route, for a world with an HLOD snapshot when no refusal applies;
    • for compositing, the pre-upscale hook and the legacy post-scene composite (interfaces/output_compositor.cpp, used for forward mobile, multiview and probes).

    The HLOD route refuses a setup through GaussianSplatRenderer::hlod_streaming_unsupported_reason() (in renderer/resident_instance_contract_publisher.cpp), whose keys lod/hlod_auto_route.h publishes. A refused setup falls back to another route. So every feature lands on three to four routes, and each route drifts: chunk-route LOD draws a prefix and does not reduce VRAM (D-01, D-06); a rotated or translated world loses HLOD (D-07); one wind or effector setting moves a streamed world off HLOD (I-02); splat shadows exist on the HLOD route only (I-03); the legacy composite is the path that dropped splats for scaled viewports (J-19).

    12.2 Options¶

    • Option A: one route. The HLOD streaming route, with the resident case as a degenerate cut and a single TileRenderParams producer (#788 Option 2, as adopted in §3).
    • Cost: finish the migration; delete the chunk route and the legacy composite.
    • Enables: feature parity by construction; one place to test.
    • Limits: every refusal in hlod_streaming_unsupported_reason() must be lifted before the fallback it protects can be deleted.
    • Option B: keep the routes and require parity. Every feature PR covers all routes, with a parity test.
    • Cost: feature work multiplied on every PR, for the life of the project.
    • Enables: no route is deleted; existing setups keep their path.
    • Limits: parity rests on a test every PR must extend; drift returns where it does not.

    Audit recommendation: A. The refusal list in hlod_streaming_unsupported_reason() is the work list.

    12.6.1 Decision¶

    One route, one residency owner, one page store with one read service, one cut:

    1. Residency. NodeResidency (lod/hlod_node_residency.h) is the single residency core of the one route, over GaussianAtlasAllocator and a pool sized once from the streaming budget inside the device ledger. This is Worlds beyond VRAM D-1 with its Step C pulled forward.
    2. Under it move the layers the beyond-VRAM program built beside the chunk route: the GSQ codec (io/gsq/**), the GSQ page source (today core/streaming_gsq_chunk_payload_source.*), PayloadReadService (io/gs_payload_read_service.*) and decode on worker threads straight into the GPU record. GaussianAtlasAllocator, the device ledger and the flythrough lane stay.
    3. On top of it sits the HLOD cut (ViewSet / CutHistory), with the producers of §4 (world cut, node instances; later per-asset trees and light views).
    4. GaussianStreamingSystem is deleted at the end of the migration, as a selection, residency and render path: its upload pipeline, regulator, visibility and eviction controllers, atlas registry, pool growth, prefix LOD and render_streaming_orchestrator.

    Clarification of D-2. "The chunk-streaming route is deleted" means item 4. It does not mean the layers in item 2; they stay and move under the one route.

    12.6.2 Why¶

    • The alternative of keeping the chunk stack as the backend under the HLOD cut was already rejected by the BV ADR ("Chunk streamer as the seed", D-1 alternatives): its unit is a fixed 64k chunk with LOD as a draw count, it has the regulator ratchet, and it has no per-node generations. The cut needs a per-node resident mask, whole-transition admission of a parent's missing children and protection of drawn nodes and their ancestors (lod/hlod_node_residency.h:154-165); NodeResidency has them, the chunk stack does not.
    • The route-neutral layers do not depend on GaussianStreamingSystem: PayloadReadService's first runtime caller is the GSQ page source (io/gs_payload_read_service.h:20-21). Rebuilding them for the HLOD route would discard working code and the codec evidence.
    • Keeping two routes with parity was rejected by D-2.

    12.6.3 Tree-less (flat) worlds reach the route through an automatically built tree¶

    Tree-less worlds reach the one route through an automatically built rule-1 tree. D2 builds it offline in the producer binary from the plain-GSQ file, using a tiled sat merge of children's payloads for interior nodes, with no error raster. This supersedes importance-prefix selection (owner decision, §12.6.6). Rule 1 is the existing merge-only identity (core/gaussian_splat_hlod_tree.h:57-69); the merge defines the geometric error and needs only child payloads (core/gaussian_splat_hlod_merge.h:190-200), so stitching needs no descendant-leaf prefix reads. The full rule-3 quality bake stays the shipping path, but is not required for M3.

    The input chunks are re-cut into fixed-lattice octree leaves; GSQ chunks are not reused as leaves. The output is a separate ordinary V4 GSQ package plus a sidecar manifest, leaving the plain input unchanged. D2 builds neither from the generator nor during import or runtime.

    Not a leaves-only degenerate cut, for these reasons, read from the contracts [inference, not run]:

    • The selector publishes a complete cut or nothing: every non-COMPLETE/EMPTY status has selected_count 0 (lod/hlod_runtime_selection.h:45-46). Residency admits a parent's missing children as one whole transition, "every run is allocated or none is" (lod/hlod_node_residency.h:160-165). A tree-less world is one synthetic parent with thousands of children, so after a teleport the whole visible set would be admitted and loaded as one transition, with no coarse image meanwhile.
    • If the visible leaves exceed the drawn budget there is no coarser frontier to fall back to, so the view draws nothing. Tier A's needed sets reached 449 chunks (Worlds beyond VRAM G-c), far above a drawn budget of 1M–4M splats. The chunk route hides this with prefix LOD, which D-2 deletes.
    • Leaves are capped at 16,384 splats (core/gaussian_splat_hlod_tree.h:45), so a flat world needs re-cutting into leaves either way.

    A leaves-only cut is used only if a CPU-only spike (the selector over a one-level tree with Tier A's leaf table at the eight checkpoint poses) shows that it publishes a complete cut within budget at every Tier A checkpoint. This leaves-only S1 control runs within D2-4 alongside the auto-tree oracle cut; its outcome is pending, not inferred from the contracts above.

    12.6.5 Known blockers to raising the HLOD caps¶

    The HLOD route is capped today at 1,048,576 leaf splats, 1,572,864 payload splats and 32,768 nodes (core/gaussian_splat_hlod_runtime_data.h:14-16, enforced for paged admission as hlod_source_admission_limit at core/gaussian_splat_world.cpp:1193-1195) and at 512 MiB of HLOD-owned GPU bytes, which also bounds the streamed atlas (:18; passed as the HLOD-owned cap into the page budget at renderer/resident_instance_contract_publisher.cpp:2220-2222, and the candidate refused above it at :2245). Raising them is blocked by:

    Status (D1, 2026-11-11, PR #1416): the count caps are now structural: the payload must fit a uint32 (MAX_PAYLOAD) and the node count the V4 reader bound of 1,048,576 (MAX_NODES), checked by gs_hlod_runtime::source_admission_refusal(). The 512 MiB cap is split: a whole-tree bundle keeps it as a deliberate budget (rendering/gaussian_splatting/lod/hlod_whole_tree_vram_budget_mb), a streamed bundle is capped by the device ledger limit and the atlas limit. The quantized record stores the full 32-bit node id (first item below). The other items below are still open.

    • 16-bit node id on the quantized path. renderer/hlod_node_pack.cpp:98 passes uint16_t(p_node) as the quantized chunk id with no range check, into the uint16_t chunk_id of PackedGaussianQuantized (renderer/gaussian_gpu_layout.h:389). It is safe only while the node cap is 32,768; above 65,535 nodes the id truncates silently [inference]. The chunk route refuses the same case explicitly (core/gaussian_streaming.cpp:4293-4299). The PR that raises the node bound adds a guard and boundary tests at 65,535 / 65,536. Refs #1413.
    • Per-frame O(N) in NodeResidency. Eviction candidates, stale-load cancel and stats loop over every node (lod/hlod_node_residency.cpp:179, :223, :285, :545, :558); BV-15.
    • In-core V4 writer. GaussianSplatHlodPagedSource::write_package takes "a resident, complete HLOD world" (io/gaussian_splat_world_paged.h:151-154); the out-of-core writer has no V4 mode yet (io/gs_world_writer.h:29, BV-18a). Tier A cannot be baked on this route today.
    • Raw V4 reads without the read service. The HLOD streamer reads each node through read_node_payload() (renderer/hlod_node_streamer.cpp:127), which opens a new FileAccess per call (io/gaussian_splat_world_paged.cpp:747).
    • Unbounded ready queue and untested throughput. Packed payloads waiting for upload are outside the 8 MiB read cap (renderer/hlod_node_streamer.h:46-51); the defaults of 32 MiB per frame and 16 jobs (:44-45) have never run above 512 MiB.
    • Pool addressing. Uploads use a uint32 byte offset (renderer/hlod_node_streamer.cpp:489), and the page budget refuses pages * page_splats > UINT32_MAX (renderer/resident_instance_contract_publisher.cpp:2224).

    Risks at scale that do not block the caps but must be watched before M3: no cross-fade (DrawnNodeGPU::fade is "written as 1.0 and not read yet", renderer/gaussian_gpu_layout.h:272), and no compaction (fragmented_groups, lod/hlod_node_residency.h:141).

    Q5 — import An auto tree at import for res:// paged-GSQ worlds comes later and is outside D2.
    Q6 — identity Pin bake digests per toolchain, with portable tiled-versus-in-core identity tests as the proof; do not claim cross-platform bake byte identity.
    Q7 — leaves-only Run the leaves-only S1 check within D2-4, at the eight Tier A checkpoint poses with the frozen drawn budget.

    Reason for replacing prefix selection. Today's chunk route draws far chunks as importance-thinned prefixes, the same mechanism as importance-prefix selection. That thinning is what opens today's far-field holes, as measured in lane run 43001272885 (G16: needed chunk not GPU-resident in 51.49 % of moving frames; drawn < 0.5 × expected in 4492 of 4614 samples) [M, owner-supplied lane result]. The HLOD ADR's measurement supports the mechanism: "Uniform thinning (C) loses coverage" and "the grass patch becomes a see-through speckle" (docs/architecture/adr-hlod-streaming.md:208-210, re-verified in the current tree; HLOD streaming §5.2). Repeating thinning in auto-tree parents would retain that cause of holes; this is why the owner chose the rule-1 sat merge. The decision and lane result do not yet prove that the future auto tree renders correctly. Distant vegetation can become softer with sat; M3 must still provide screenshots and the repaired gates' drawn-fraction evidence against the frozen chunk-route reference.

    The dependency-ordered D2-0–D2-5 PR split and required evidence are recorded in Worlds beyond VRAM §10, P3. BV-18a/b supply out-of-core V4 writing and W13; BV-C4 is required for Tier A (uncompressed V4 is too large). D2-1/2 can proceed alongside that writer/codec work. Loading and streaming Tier A for M3 additionally need D1's shared layers and cap work, including BV-16a, and #1417 must be fixed before M3. D2's CPU preparation and oracle checks alone make no rendering claim. This R0 amendment changes no code, workflow, guard, threshold or runtime acceptance gate.
